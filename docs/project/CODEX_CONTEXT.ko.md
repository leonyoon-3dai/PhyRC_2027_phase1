**정리일: 2026-11-06. 코드 확인 기준: `f79f61bccab5ad171b86598ac48dcfd03aef6a4a`.**

최근 검토한 데이터 수집, VLA 학습, 행동 실행, RGB-D 인식과 정책 개선 내용을 새 서버의 개발용 Codex가 이어받기 위한 문서입니다. 이번 변경은 문서만 추가합니다. 새 서버 실행, 새 시연, 학습, 점수 개선을 수행했다는 뜻이 아닙니다.

## 1. 이번 작업에서 먼저 할 일

두 Stretch 4가 티셔츠를 집어 마네킹에 입히는 과정을 **공개 관측으로 짧게 행동하고 다시 확인하는 방식**으로 수집합니다. 사람이 자연어로 목표와 수정을 전달하고 Codex CLI가 제한된 실행기를 사용합니다. 우선 접근, 양쪽 파지, 들어 올리기의 유효한 구간부터 확보합니다. 장기 목표는 한 번의 연속된 시도에서 전체 착의 조건을 달성하고, 그 시연으로 학습한 정책을 다른 배치에서 평가하는 것입니다.

첫 실행에서 수집, 모델 변경, RL, 물리 엔진 교체를 동시에 진행하지 않습니다. 현재 README의 **수집 연결 우선** 원칙을 유지합니다. 이전 연구 문서의 다른 모델 추천이나 날짜별 계획은 비교 후보이며 현재 기준선을 자동으로 바꾸지 않습니다.

| 순서 | 읽을 문서 | 필요한 내용 |
|---|---|---|
| 필수 | 이 문서 | 현재 상태, 첫 실행 범위, 우선순위와 종료 기록 |
| 수집 구현 | [자연어 수집과 데이터 보존](research/COLLECTION_AND_RECOVERY_CONTEXT.ko.md) | 제어권, 공개 관측, 기록, 되감기와 재시작, 점수 |
| 학습 연결 | [VLA 학습과 실행의 실제 계약](research/VLA_TRAINING_CONTEXT.ko.md) | 32D state, 18D action, flow matching, LoRA, 정규화, chunk와 RL |
| 후속 실험 | [RGB-D 인식과 정책 확장](research/PERCEPTION_POLICY_CONTEXT.ko.md) | 5개 카메라, 깊이, 기하, 모델 비교, 최신 방법과 검증 순서 |

행동을 생성하는 세션에는 이 개발 문서나 저장소 전체를 전달하지 않습니다. 개발 문맥에는 평가기, 원시 자료, 내부 구현이 포함될 수 있으므로 행동 세션의 공개 관측 문맥과 분리합니다.

## 2. 이미 있는 것과 아직 없는 것

| 구분 | 확인한 상태 | 다음 판단 |
|---|---|---|
| 사람 시연 | 접근, 파지, 들기, 운반의 부분 시연과 영상이 있음 | 실제 점수와 전체 착의 성공은 별도 검증 |
| 실행 및 기록 경계 | `boundary.py`, `collect_operator.py`, HDF5 writer가 있음 | CLI 연결과 실행 격리는 추가 구현 |
| 기존 모델 호출 | `gpt_client.py`는 API 기반 작은 동작 연결 시험 | Codex CLI 수집기로 설명하거나 그대로 대체하지 않음 |
| 자동 수집 평가 | 기본 경로에 공식 evaluator가 연결되지 않음 | 동일 시도의 평가 결과를 신뢰된 실행기 측에서 별도 저장 |
| 학습 데이터 승인 | `approved_pipeline_test`만 허용 | 실제 시연용 출처와 승인 상태 추가 |
| 현재 VLA | OpenPI/JAX 기반 π₀.₅ LoRA 학습 및 묶음 추론 코드 | 사람 시연 기반 유용한 정책 성능은 확인 전 |
| 과거 학습 | 63개 scripted transition으로 30 update의 연결 시험 | 성공 시연 학습이나 성능 향상의 근거로 사용하지 않음 |
| 새 입력, 다른 모델, RL | 검토한 후속 실험 | 기준선을 만든 뒤 한 변수씩 비교 |

과거 자료 위치와 리비전은 [복원 안내](RECOVERY.ko.md), [10월 26일 종료 기록](END_20261026.ko.md), [11월 3일 종료 기록](END_20261103.ko.md)에서 필요할 때 확인합니다. 원시 자료가 보존됐다는 기록, 학습용 변환 완료, 원격 재다운로드 검증은 서로 다른 상태입니다. 현재 서버나 원격 자료가 그대로 존재한다고 추정하지 않습니다.

## 3. 바꾸지 않을 계약

- 공식 환경의 물리, 형상, 행동 한계, 평가식을 편의상 수정하지 않습니다.
- 공개 카메라, 공개 로봇 상태, 허용된 정적 보정 정보만 행동 및 학습 모델에 전달합니다. 내부 옷 상태나 평가기 기하로 행동 정답을 만들지 않습니다.
- 정규화 명령 `float32 (2,9)`와 로봇 순서를 유지합니다. 각 행의 앞 8개는 속도 명령, 마지막은 gripper 의도입니다. 목표 위치, joint delta, 그리퍼 폭으로 조용히 재해석하지 않습니다.
- 정책 20 Hz, 제어 60 Hz, 물리 240 Hz를 구분합니다. 미리보기 FPS, CLI 응답 시간, flow 생성 반복 횟수는 이 주기와 다릅니다.
- 원본 데이터는 보존하고 승인 구간, 학습 분할, 변환 결과는 별도 manifest로 관리합니다.
- 누적 점수 50, 착의 `success`, 데이터 `complete`, 에피소드 `done`을 별도 필드로 기록합니다.
- L40S 한 대에서 수집, 렌더링, 학습과 평가는 우선 순차 실행합니다. 큰 모델 다운로드나 기존 자료 전체 복원을 첫 단계에 넣지 않습니다.

## 4. 새 서버의 최소 시작 순서

설치 명령과 전제 조건은 [START_HERE.ko.md](START_HERE.ko.md)를 그대로 따릅니다. 새 명령을 실제 구현된 것처럼 만들지 않습니다.

1. `git status --short`와 실제 HEAD, 하드웨어, 드라이버, 컨테이너 GPU 접근, RAM과 디스크를 기록합니다.
2. 공식 환경을 구성하고 종료 코드 0과 `PHYRC-SMOKE-PASS`를 확인합니다. CPU 검사를 실행합니다.
3. 서버의 `codex --version`과 `codex exec --help`를 확인합니다. 이미지 입력, 구조화 출력, 에피소드별 세션 사용과 모델 접근을 작은 입력으로 확인합니다.
4. 개발 세션과 행동 세션을 분리하고 기존 JSON Lines 실행기와 연결합니다. API 호출 경로로 자동 전환하지 않습니다.
5. 모델 없이 작은 동작, 정지, 정상 종료, HDF5 시간 및 실제 명령 기록을 확인합니다.
6. 행동 세션을 연결해 공개 영상으로 결과를 다시 관측합니다. 점수는 별도 검수 기록으로만 저장합니다.
7. 짧은 시도 10회를 표본으로 수집 효율과 데이터 품질을 봅니다. 10회는 학습에 충분하다는 기준이 아닙니다.

첫 실행의 완료 기준은 **유효한 짧은 수집 1회와 재현 가능한 실행 기록**입니다. 전체 착의나 정책 학습까지 끝내야 하는 것은 아닙니다. 수집 중 문제가 드러나면 해당 경계를 고치고 다시 확인합니다.

## 5. 핵심 기술 질문과 확인할 증거

| 질문 | 코드 및 데이터에서 확인할 것 |
|---|---|
| 두 로봇을 같은 시점에 제어하는가 | `(2,9)` 두 행을 하나의 policy step에 적용하고 두 로봇 관측 시각을 함께 기록 |
| 모델의 말과 실제 명령이 같은가 | 요청 JSON, 제한 후 적용 action, 적용 step 수를 나눠 저장 |
| 정지했다고 정말 멈추는가 | 호출 대기, timeout, 중단 시 시뮬레이션 진행과 잔류 명령 확인. gripper 0은 열기가 아님 |
| 데이터로 학습할 수 있는가 | 전체 episode의 시간, shape, NaN, 카메라 순서, 실제 행동, reset 경계 검수 |
| LoRA가 실제 반영됐는가 | trainable parameter 목록, 전후 가중치 차이, 저장 후 재로드, 동일 입력 출력 비교 |
| 손실 감소가 동작 개선인가 | 고정된 배치와 예산에서 closed-loop rollout을 별도로 평가 |
| 깊이와 추가 영상이 필요한가 | 같은 데이터와 학습량으로 입력만 바꾸고 단계 진행도, 지연, VRAM과 실패 유형을 비교 |
| RL을 시작할 때인가 | 기본 정책의 유용한 접촉과 반복 가능한 reset, 유효 reward, critic 입력 경계가 먼저 확보됐는지 확인 |

## 6. 구현 우선순위

| 수준 | 수행 범위 | 산출물 |
|---|---|---|
| P0 | 공개 관측, CLI 연결, 실행, 정상 종료와 기록 | 작은 수집, 오류 사례, 실제 명령, 파일 검수 |
| P1 | 단계 표시, 사람 개입, 별도 평가, 비파괴 보존 | episode 및 segment manifest, 점수와 QC, 원격 백업 검증 |
| P2 | 승인 데이터의 π₀.₅ 기준선 | train/validation split, 정규화 통계, 학습 파라미터 감사, 재로드, rollout |
| P3 | 필요한 한 가지 비교 | 실행 chunk 길이, 작은 정책 또는 깊이 보조 중 병목에 맞는 하나 |

논문 재현과 대회 점수 개선은 같은 실험이 아닙니다. 공개 코드를 가져오더라도 입력, 행동 의미, 모델 자산, 라이선스, 메모리, 지연과 평가 조건을 먼저 확인합니다.

## 8. 세션 종료 시 남길 한 묶음

`docs/project/STATUS.md`와 날짜별 세션 문서에 다음 정보를 남깁니다. 이는 새로 구현할 기록 항목의 기준이며 현재 파일이 모두 자동 생성된다는 뜻은 아닙니다.

- 코드 HEAD와 변경 파일, 공식 환경과 컨테이너 식별자, 자산 및 의존성 버전.
- 실행한 명령, 모델 및 CLI 설정, 프롬프트 해시, 허용 관측 구성.
- run/episode/segment ID, 데이터 출처, 사람 개입과 중단 사유.
- 파일 완료 여부, 전수 QC, 평가 `valid`, 실제 점수, success 검증 여부.
- 업로드 위치, 고정 리비전, SHA256, 실제 재다운로드 검사 결과.
- 지금 실패한 가장 작은 재현 사례와 다음 한 가지 작업.

터미널 종료와 서버 요금 종료는 별개입니다. 서버 정리 전에 필요한 원본이 다른 저장소에서 복원되는지 확인합니다. 저장소에는 코드와 작은 검수 결과만, 큰 영상과 데이터 및 모델은 별도 자료 저장소에 둡니다.
