# 왜 5점에서 멈췄고, 다음 10점을 어떻게 확인할까

[현재 상태](STATUS.md) · [E15 최종 검토](../collection/reviews/20261106-astra-opening264-001.ko.md) · [사실·가설·다음 후보](SESSION_WRAPUP_20261106.ko.md) · [시도별 영상](../gallery/README.ko.md)

**현재 5점은 픽업입니다. 다음 목표는 픽업 점수를 얻은 같은 시도에서 첫 소매 +5점을 얻어 원점수 10점을 확인하는 것입니다.** 첫 소매는 손이 소매를 통해 밖으로 나온 것을 평가기가 확인해야 합니다. 손이 천 뒤로 사라지거나 로봇이 마네킹 가까이 간 것만으로는 부족합니다. 원점수 10점도 전체 착의 성공은 아닙니다. 픽업 5점은 순위용 착의 점수율 분자에서 제외됩니다.

## 확인한 사실과 아직 모르는 것

| 질문 | 실제로 확인한 것 | 아직 확정할 수 없는 것 |
|---|---|---|
| 옷을 들었나? | E15 초기 lift·그리퍼 높이가 증가했고 천의 층 분리가 보임 | 통과 가능한 몸통 입구를 안정적으로 열었는지 |
| 두 베이스가 같이 움직였나? | 운반 D5–D15 이동 거리 차이 최대 **0.260mm** | 일정 간격이 천의 장력·파지 유지까지 보장하는지 |
| 양쪽이 각각 잡고 지지했나? | 함께 들고 운반했고 마지막에는 robot1 쪽에 천이 매달림 | 처음부터 각 파지가 독립적으로 하중을 지지했는지 |
| 손이 들어갔나? | 손 근처에서 손·천·그리퍼 가림이 반복됨 | 가려진 손이 입구를 통과했는지, 외부 천 뒤에 있는지 |
| robot0는 왜 벌어졌나? | 닫기 목표 유지 중 손가락 원점 거리 **61.492→133.403mm**. 이후 명시적 열기·철수 | 정확한 접촉 상대, 슬립·부착 해제·간섭의 원인 |
| 기록·종료가 문제였나? | E09 오류 수정·회귀 검증 완료, E15 **611/611전이** 검사 통과 | 파일 품질 통과가 착의 기술이나 학습 승인을 뜻하지 않음 |

위 거리는 손가락의 원점 사이 거리이지 접촉면 간격이나 파지 센서가 아닙니다. “처음부터 robot1이 못 잡았다”, “베이스 비동기 때문이다”, “depth만 넣으면 해결된다”는 결론은 현재 근거로 확정하지 않습니다.

## 다음에는 무엇을 작게 확인할까

아래는 **미실행 제안**입니다. 사용자가 재개를 요청하면 환경·복원·짧은 연결 검사를 마친 뒤 한 가지 진단을 선택합니다. E15와 700분기를 자동 재실행하지 않습니다.

| 순서 | 한 번에 확인할 질문 | 행동·관측의 설계 | 진행 또는 중단 기준 |
|---|---|---|---|
| **1. 독립 지지** | 각 그리퍼가 실제로 천을 지지하는가? | 테이블 지지 가까이에서 한쪽씩 작은 움직임. 움직인 쪽 천의 반응과 반대 로봇 실제 변위를 함께 기록 | 양쪽을 각각 확인하면 입구 준비로 진행. 천이 따라오지 않거나 구분 불가하면 파지 준비로 돌아감 |
| **2. 입구·손·그리퍼 분리** | 손을 통과시킬 내부 경계와 여유가 보이는가? | 잡은 모서리·그리퍼에 손을 바로 맞추는 대신 천의 안쪽 경계·손·양 그리퍼가 보이는 짧은 접근 비교 | 경계가 계속 보이면 접근. 가림 반복이나 한쪽 형상 변화가 커지면 멈추고 관측·준비 변경 |
| **3. 공개 depth 질의** | 관계는 보이지만 앞뒤 거리만 모호한가? | 같은 공개 관측에서 선택 픽셀의 depth를 확인하는 후보 도구 검토 | 도구의 CLI 2턴·수집 통합 검증 이후 비교. 가려진 입구·손·접촉을 추정하는 정답 도구로 사용하지 않음 |
| **4. 첫 소매 검증** | 실제 통과와 추가 득점이 일치하는가? | 공개 영상으로 접근·통과·유지를 기록하고 종료 후 공식 평가기 항목을 검토 | **pickup 5 + first sleeve 5 = 원점수 10** 확인. 미득점은 억지 성공 라벨 없이 실패/불확실로 보존 |

한 단계에서 의문이 남으면 다음 도구를 계속 추가하기보다 그 단계를 다시 설계합니다. 고정 중립 6전이(0.3 simulation초)는 대기일 뿐 안정화 보장이 아니므로 실제 위치 변화와 목표 잔차를 함께 봅니다. 기존 제어·물리·평가 정의를 임의로 바꾸지 않습니다.

## 다음 시도의 최소 기록표

| 기록 | 남기는 이유 |
|---|---|
| run ID·실행 소스·모델/CLI·부모/source group | 어떤 코드·자료에서 출발했는지 재현 |
| 바꾼 조건 한 가지와 가설 | 결과가 달라진 이유를 좁힘 |
| 전후 공개 RGB·depth·로봇 실제 상태·행동 | 모델의 주장과 실제 움직임을 비교 |
| 재실행/모델/중립 전이 수·simulation초·실제 경과시간 | 새 시연량과 비용을 중복 없이 계산 |
| 파일 마감·전수 검사·득점 항목·success·학습 승인 | 데이터 정상성, 과제 결과, 학습 사용 허가를 구분 |

예를 들어 **새 모델 호출 최대 6회**로 독립 지지 진단을 제한하는 방안이 있습니다. 이는 **실측 성능이나 확정 실행 조건이 아닌 예산 선택 후보**이며, 재실행에 드는 호출 외 시간은 따로 기록합니다. 호출 한도를 채우는 것보다 가설을 구분했는지가 종료 기준입니다.

점수·평가기 내부 상태는 actor 입력에 넣지 않고 결과 검토에 사용합니다. 같은 E07 원본의 분기를 독립 성공률 표본으로 세지 않습니다. 진단·실패 영상도 유용한 근거지만 자동으로 성공 시연이나 학습 승인 자료가 되지는 않습니다.

## VLA·RL은 언제 연결할까

우선 **무엇을 잡고, 어떤 입구를 어떻게 유지하며, 손이 통과했음을 무엇으로 확인할지**를 구분합니다. 아직 첫 소매를 재현하지 못한 상태에서 큰 모델 학습부터 시작하면 관측 부족·파지 문제·행동 선택 문제 중 무엇을 학습해야 할지 불명확합니다.

반복 가능한 진전과 검수 기준이 생기면 승인 자료로 작은 정책 학습 → 짧은 로컬 실행 → 실패 분류를 연결합니다. 그 뒤 VLA 미세조정이나 RL이 개선할 대상을 정합니다. **현재 문서는 다음 진단 계획이며 새 구현·실험·학습 결과를 추가하지 않았습니다.**
