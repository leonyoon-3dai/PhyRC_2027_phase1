## 1. 어떤 챌린지인가

PhyRC 2027 Phase 1은 **두 대의 Stretch 4가 앉아 있는 마네킹에 티셔츠를 입히는 시뮬레이션 챌린지**입니다. 정책은 공개 카메라와 로봇 상태를 보고, 두 로봇의 행동을 함께 결정합니다.

| 구분 | 내용 |
|---|---|
| 작업 | 옷에 접근하고 잡아 올린 뒤, 소매와 목구멍을 맞춰 마네킹에 입히기 |
| 행동 | 매 0.05초마다 `float32 (2,9)` 반환. 두 행은 두 로봇의 명령 |
| 점수 | 픽업과 착의 항목을 합해 최대 50점 |
| 순위 | 픽업을 제외한 착의 점수를 착의 시간으로 나눈 `points/s` |
| 최종 평가 | 같은 세 개 숨은 배치에서 얻은 점수의 산술평균. 실패 배치도 포함 |
| 실행 예산 | 배치마다 시뮬레이션 시간과 정책 호출 시간을 합해 900초 |

참고: [공식 대회](https://emprise.cs.cornell.edu/phyrc/challenge-2027/) · [Codabench](https://www.codabench.org/competitions/18366/) · [공식 정책 안내](../competition/POLICY.md)

## 2. 50점은 어떻게 쌓이는가

아래 순서는 이해를 돕는 예시입니다. 실제 득점 순서는 달라지거나 여러 항목을 동시에 획득할 수 있습니다. **한 번 얻은 점수는 이후 자세가 바뀌어도 유지됩니다.**

| 항목 | 점수 | 평가기가 확인하는 조건 |
|---|---:|---|
| 픽업 | 5 | 같은 그리퍼가 잡은 옷 부분을 파지 위치보다 5 cm 이상 올리고 시뮬레이션 3초 유지 |
| 첫 소매 | 5 | 첫 손이 소매를 통과해 손목과 손끝이 밖으로 나옴 |
| 반대쪽 어깨 | 5 | 옷 일부가 반대쪽 어깨 관절 위로 넘어감 |
| 두 번째 소매 | 5 | 다른 손이 다른 소매를 통과해 밖으로 나옴 |
| 왼쪽 위팔 | 5 | 왼쪽 소매가 위팔 일부를 덮음 |
| 오른쪽 위팔 | 5 | 오른쪽 소매가 위팔 일부를 덮음 |
| 목 | 10 | 가슴이 옷 안에 있고 머리와 목이 목구멍으로 올바르게 나옴 |
| 앞면 방향 | 10 | 머리가 나온 상태에서 V넥이 앞으로 향하는 조건을 0.5초 유지 |
| **합계** | **50** | 픽업 5점과 착의 45점 |

두 손이 같은 소매로 나온 상태는 인정하지 않습니다. 위팔은 각각 5점 또는 0점이며, 덮인 길이에 비례하는 점수는 아닙니다. 목 항목에는 유지 시간 조건이 없습니다. 앞면 방향은 정면에서 ±45° 이내이고 투영된 앞 방향 길이가 2 cm 이상인지를 확인합니다. 몸통 덮임과 아래팔 자체에는 별도 점수가 없습니다.

### 누적 50점과 착의 성공은 따로 확인

**`success=true`는 두 손이 서로 다른 소매 밖에 있고, 머리·목이 밖에 있으며, 옷 앞뒤 방향이 올바른 조건을 동시에 0.5초 확인한 상태**입니다. 서로 다른 순간에 점수를 쌓아 50점을 얻었더라도 이 동시 조건을 만족하지 않을 수 있습니다.

| 확인할 상태 | 답하는 질문 |
|---|---|
| `raw_points` | 지금까지 어떤 점수 항목을 획득했는가? |
| `success` | 전체 착의 조건을 동시에 유지했는가? |
| 기술 검사 통과 | 파일과 관측·행동·시간 기록이 올바른가? |
| 학습 승인 | 이 구간을 실제 정책 학습에 사용해도 되는가? |

조건의 원문과 JSON 필드는 [공식 평가 안내](../competition/EVALUATION.md)를 따릅니다.

## 3. 순위는 points/s로 결정

```text
착의 점수 = raw_points − 실제로 획득한 pickup 점수       최대 45점
착의 시간 = 마지막 착의 득점 시각 − 옷과 마네킹의 첫 접촉 시각
points/s  = 착의 점수 ÷ 착의 시간                     시뮬레이션 초
```

| 예시 사건 | 시뮬레이션 시각 | 획득 점수 |
|---|---:|---:|
| 픽업 | 20초 | +5 |
| 옷이 마네킹에 처음 접촉 | 100초 | 없음 |
| 첫 소매 | 250초 | +5 |
| 반대쪽 어깨 | 340초 | +5 |
| 목 통과, 이후 추가 착의 득점 없음 | 500초 | +10 |

이 예시의 누적 점수는 **25점**입니다. 픽업을 뺀 착의 점수는 **20점**, 착의 시간은 **500−100=400초**, 순위 점수는 **20÷400=0.05점/초**입니다. 같은 20점을 첫 접촉 후 200초 안에 얻으면 0.10점/초가 됩니다.

- **픽업만 5점이면 순위 점수는 0점/초**입니다. 착의 점수가 필요합니다.
- 마지막 착의 득점 이후 기다리기만 하면 기존 `points/s`는 변하지 않습니다.
- 새 착의 득점은 누적 점수와 경과 시간을 함께 갱신합니다. 매우 늦은 추가 득점은 비율을 낮출 수도 있습니다.
- 첫 접촉 후 옷이 떨어져 접촉을 잃어도 다음 득점까지의 시간은 포함합니다.
- 첫 접촉은 240 Hz 물리 tick의 충돌 메시 접촉 범위로 정하고, 득점은 20 Hz 샘플에서 확인합니다.
- 접촉 후 착의 점수가 없으면 `no_dressing_points`로 0점입니다. `no_contact` 등 null rate도 여러 배치 평균에서는 0으로 집계합니다.
- 이미지 빌드 실패, 실행 중 충돌, 유효 결과 없음도 해당 배치 0점입니다. 평가 기록의 `valid=false`를 유효한 부분 점수로 보고하지 않습니다.

## 4. 시간 네 가지를 구분하기

| 시간 | 계산 또는 측정 범위 | 어디에 쓰는가 |
|---|---|---|
| 로봇 시간 | 실행 step 수 × 0.05초 | 로봇과 옷이 움직인 시뮬레이션 진행량 |
| 공식 에피소드 예산 | step마다 0.05초 + 정책 호출 소요 시간 누적 | 공식 900초 제한 |
| 실제 경과 시간 | 초기화, 물리·센서 계산, 모델 호출, 기록 등 실제 소요 | 서버 비용과 수집 효율 분석 |
| points/s 분모 | 첫 접촉부터 마지막 착의 득점까지의 로봇 시간 | 순위 점수 계산 |

정책이 매번 50 ms를 쓰면 한 step은 예산 0.10초를 소비합니다. 900초 예산에서는 약 9,000 step, 즉 로봇 시간 약 450초를 실행할 수 있습니다. 이는 일정한 호출 시간을 가정한 설명용 계산입니다.

현재 공식 실행 코드는 `policy(obs)` 호출 시간을 측정해 0.05초와 더합니다. **물리·센서 계산을 하는 `env.step()`의 실제 소요 시간 자체를 이 예산에 더하지 않습니다.** 따라서 서버가 느리면 900초 평가에 실제로 몇 시간이 걸릴 수 있습니다. 두 로봇을 함께 움직여도 하나의 step은 0.05초입니다.

## 5. 공식 평가 종료와 시연 수집 중지는 다르다

| 구분 | 이 기준 버전에서의 동작 |
|---|---|
| 공식 정책 평가 | `terminated`, `truncated`, 시간 예산 소진 중 하나에서 반복 종료 |
| 기본 공식 실행 경로 | `evaluator=None`으로 환경 생성. 40점·50점·success 기반 조기 종료 조건 없음 |
| 정책의 0 행동 | 속도 정지와 그리퍼 기존 의도 유지. 평가 종료 신호가 아님 |
| 참가자 자동 수집 | `--review-points`, 결정·전이 예산, 사용자 중지 등 수집 운영 조건 사용 |
| 점수 계산 | 평가가 계속 실행돼도 마지막 착의 득점 뒤의 대기는 분모를 늘리지 않음 |

공식 코드 근거: [`evaluate_policy.py`](../../scripts/evaluate_policy.py), [`DressingEnv.step`](../../src/PhyRC_Sim/Policy/environment.py), [`EvaluationSession.for_policy`](../../src/PhyRC_Sim/Policy/evaluation_live.py). 성공 판정은 별도 평가기가 기록하며 기본 환경의 종료 신호에 자동 연결되지 않습니다. 참가자 수집기에서 5점이나 50점에 멈추는 설정을 공식 제출 평가기의 종료 규칙으로 설명하지 않습니다.

## 6. 공개 관측으로 행동하고, 점수는 별도로 검수

| 정보 또는 사용 방법 | 허용 범위 |
|---|---|
| 지정 카메라 5개 | RGB, depth, depth_valid를 정책 입력으로 사용 |
| 공개 로봇 상태 | 자신의 관절·속도·base 위치와 속도, 그리퍼·손끝 상태, 제어 목표, 이전 행동, 시뮬레이션 시간 |
| 카메라 보정과 로봇 기하 | 공개 보정값·관절 이름·단위·행동 크기, 로봇 자신의 공개 기하 사용 |
| 영상 기반 추정 | 공개 RGB-D로 옷·물체 위치나 특징을 추정하는 모델·제어기 사용 |
| 점수와 success | 시연 선택·분석·학습 보상에 사용. 정책 입력이나 행동 정답으로 전달하지 않음 |
| 내부 기하 기반 보상·종료·reset | 학습 중 허용. actor·critic·추론 모델·교사 입력과 행동 라벨로 전달하지 않음 |
| 금지된 행동 입력 | 옷 입자·정점, 옷·마네킹·의자 정답 위치, 내부 파지 anchor, 평가 기하, 정답 segmentation |
| 금지된 자료 입력 | audit, 평가 JSON, raw state, 자유 시점 viewport, spawn seed, 물체 위치를 드러내는 동적 카메라 행렬 |

로봇 자신의 공개 base world pose는 허용된 위치 정보입니다. 옷이나 마네킹의 정답 위치를 읽는 것과 구분합니다. 공식 옷·마네킹 자산을 다른 시뮬레이터에 옮겨도 특권 정보로 행동 라벨·자동 시연·교사를 만드는 것은 허용되지 않습니다.

사전학습 모델과 외부 데이터는 사용 출처를 기록합니다. 물리·기하·구동 제한이나 평가기를 바꿔 점수를 높이지 않습니다. 수집 HDF5의 기본 `rewards=0`은 실제 착의 보상이 아니며, `done`도 성공 라벨이 아닙니다. 로컬 형식 검사를 통과했다고 규정 준수가 인증되는 것은 아닙니다.
