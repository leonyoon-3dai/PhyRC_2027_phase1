사용자 요청으로 오늘 실행을 종료했습니다. **다음 세션은 기존 UI를 사용하는 사람 조작 테스트**입니다. 텍스트 입력은 사용하지 않으며, 새 텍스트 제어 기능을 먼저 개발하지 않습니다. 과거 수집 자료·오늘 짧은 자료는 다음 테스트의 선행 조건이 아닙니다. 기존 자료는 삭제하지 않았습니다.

## 오늘 검증한 것

- 소스 `e2b353e6ce1e6fd09472b8ea35a4b98e1569c1da`에서 공식 고정 Isaac Sim 6.0.1 환경 build/prepare/smoke 통과: 170.60/6.74/219.72초.

- smoke: 두 로봇 이동, 그리퍼 toggle, 유한 의복 좌표, 저장/불러오기 좌표 오차 0. 접촉·파지 유지까지 포함하는 복원 검증은 아닙니다.
- 맥북 Chrome 영상과 조작을 사용자가 확인. 서버에서도 키 입력과 로봇 이동 확인.
- 사용자 피드백: 텍스트 입력보다 기존 버튼·방향 화살표·키보드 UI 선호. 내일 동일 UI로 사용성 테스트를 이어감.

## 연결 문제와 실제 해결

이 서버의 외부 조회 IP는 송신 주소이며 직접 viewer 접속은 실패했습니다. 서버 방화벽에 맥북 패킷이 도달하지 않았고 `/etc/brev/environment-context.json`에는 SSH/Jupyter만 등록되어 있었습니다.

사용자 브라우저 인증 후 **Brev CLI로 TCP 8210/8211/49100, UDP 47998 포트를 자동 등록**해 해결했습니다. CLI `--allow`로 실제 맥북 IPv4/32만 허용했습니다. 중계 트래픽은 NetBird `wt0`를 통해 도착하므로 알려진 Brev gateway peer만 streaming chain에 허용했습니다. 임의로 전체 인터넷 방화벽을 열지 않았습니다.

외부 포트는 내부 포트와 다릅니다. viewer URL에는 `keyboardPort`, `signalPort`, `mediaPort`를 지정하고 `STRETCH4_VIEWER_ORIGIN`은 외부 viewer origin과 정확히 일치시켰습니다. 새 서버에서 기존 IP·포트·peer를 재사용하지 않습니다. 실제 주소·계정 인증·개인 로그는 공개 저장소에 기록하지 않습니다. 재현 명령은 [START_HERE](START_HERE.ko.md)를 따릅니다.

## 내일 0 → 50점: 단계별 저장·재시작 시험

점수 50은 목표이고 오늘의 실측 결과가 아닙니다. 시작 점수도 실제 평가 절차로 확인합니다. 접근/파지/운반 등을 임의의 10·20·30점에 대응시키지 않습니다. 단계별 점수 기준은 공식 평가 기준과 실제 관찰로 정합니다.

1. 서버 선택 → 최소 환경 점검 → 동일 UI 복원. 모델·과거 데이터 전체 복원은 불필요합니다.
2. 짧은 UI 이동·키 놓기·정상 종료/저장을 확인하고 새 시도를 시작합니다.
3. 시작 상태/점수 → 접근·정렬 → 파지·들기 → 운반 → 착의 단계로 시도합니다. 각 단계의 실제 점수(가능할 때), run/episode/tick, 사용자 판단과 실패 원인을 기록합니다.
4. 단계 달성 시 원본을 보존하고 구간 경계를 기록합니다. **기록 구간 저장 ≠ 실행 중 물리 상태 checkpoint**입니다. 서로 다른 상태의 기록을 연속 궤적으로 이어 붙이지 않습니다.
5. UI의 `P` 초기화 동작과 데이터 episode 경계를 먼저 검증합니다. 현재 브라우저 키 매핑/서버 allowlist에는 F1~F5가 없으므로, 기존 시뮬레이터의 slot 기능을 UI에서 사용하려면 명시적으로 연결하고 작은 테스트를 먼저 해야 합니다. 오늘 연결·검증한 것으로 표시하지 않습니다.
6. checkpoint를 저장 → 소폭 움직임 → 복원 → 계속 조작하여 로봇/의복·속도·파지·제어 목표·접촉·평가 상태를 비교합니다. smoke의 좌표 오차 0은 정확한 solver 복원·파지 유지·crash recovery 증거가 아닙니다.
7. 복원을 신뢰할 수 없으면 초기 상태 재시작 후 사람이 재실행합니다. 정밀 되감기나 무손실 중단 복구를 약속하지 않습니다.
8. 각 단계 기록과 재시작/복원이 확인된 뒤 첫 50점 시도를 이어갑니다. 점수는 보고·선택용이며 자동 제어 입력으로 넘기지 않습니다.

다음 작업은 사용자 재개 요청 후 시작합니다. 오늘 종료 요청을 무시하고 GPU 실행·새 기능 테스트를 자동 재개하지 않습니다.
