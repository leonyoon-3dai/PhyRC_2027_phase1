# HolidayFactory 1.0 검토와 PhyRC 적용 후보

작성일: 2026-11-15. 대상: 개발용 Codex와 사용자의 연구·설계 검토.

이 문서는 채팅에서 검토한 논문과 PhyRC 적용 아이디어를 기록한다. 특정 엔진·모델·조작 방법을 채택한 결정이나 구현 결과가 아니다. 사용자의 현재 방향은 여러 방법을 비교하며 E36의 경험에서 추가 착의 득점으로 이어지는 시스템을 모색하는 것이다. 실제 실행 범위는 [COLLECTION_PLAN](../../COLLECTION_PLAN.md), E36 근거와 시스템 선택지는 [이어가기 분석](2026-11-15-e36-continuation-options.ko.md)을 따른다.

## 2. PhyRC에 적용할 때의 해석 범위

**이하 내용은 현재 PhyRC 기록을 바탕으로 한 우리의 설계 제안이다. 논문이 온라인 착의 감독기, 사람 개입, 소매 통과 개선을 구현하거나 검증했다는 뜻이 아니다.**

E36에서 확인한 로봇 이동, 천의 외관 변화, 모델의 정체 판단, 공식 착의점 0은 서로 다른 사실이다. 이를 하나의 성공/실패 문장으로 합치지 않고 다음 조작을 선택할 수 있는 근거로 남기는 것이 목표다. 물리를 교체하거나 종료 제한만 늘리는 방법을 먼저 정답으로 정하지 않는다.

| 검토 후보 | 해결하려는 문제 | 확인해야 할 효과 |
|---|---|---|
| 공개 상태로 실행 효과 계산 | 명령과 실제 파지점 이동의 차이 | 수정 방향이 실제 운동으로 연결되는가 |
| 천·손 관계의 시각 검수 | 이동했지만 진입은 불명확한 상황 | 자유 경계의 변화와 단순 가림을 구분하는가 |
| 정체 종료 전 재검토 | 가능한 대안을 찾기 전에 수집이 닫히는 상황 | 유효한 복구가 늘고 반복 정체는 억제되는가 |
| 사람 단독 키보드 조작 | 현재 형상에서 가능한 성공·복구 경로가 미확인 | 공개 관측과 공식 제어로 경로를 재현할 수 있는가 |
| 텍스트 피드백·제어권 전환 | 사용자의 관찰을 실행에 반영하기 어려움 | 전달·인계·실행 경계를 정확히 기록하는가 |
| 모델 critic 또는 진행 판별기 | actor 판단의 누락·오류 | 실제 근거와 대조했을 때 오판이 줄어드는가 |
| 후속 VLA·RL | 검수된 진행·복구 경험을 정책에 반영 | 동일 평가 조건에서 추가 득점이 재현되는가 |

이 후보들은 대체하거나 조합할 수 있다. 사람 조작을 모든 실험의 필수 선행 조건으로 고정하지 않으며, critic 추가나 모델 교체도 효과 검증 없이 기본 구조로 채택하지 않는다.

## 3. 측정된 실행 결과를 다음 결정에 연결하기

각 행동에는 다음 기록을 연결하는 방안을 검토한다. 구현 전 제안 스키마이며 현재 로그가 이 구조를 완전히 제공한다는 뜻은 아니다.

| 필드 | 기록 내용 | 구분할 것 |
|---|---|---|
| 관측 경계 | run, step, 카메라, 시뮬레이션 시간 | 다른 replay의 유사 화면과 동일 상태 |
| 행동 주체 | 사람·actor·감독기 정착 명령 | 제안한 행동과 실제 적용 행동 |
| 목적과 유지 조건 | 바꿀 한 요소와 보존할 관계 | 모델의 의도와 관측된 사실 |
| 실제 운동 | 관절·base·grasp의 전후 변화 | 명령 구간과 정착 구간 |
| 천의 반응 | 국소 동행, 주름, 자유 경계 후보의 변화 | 천의 재료점 측정과 시각적 추정 |
| 같은 손의 관계 | 손·전완·자유 경계 후보의 상대 변화 | 진입과 가림 |
| 불확실성 | 확인됨·불명확·보이지 않음, 해당 근거 | 모르는 상태와 실패 확정 |
| 다음 실험 | 새 접근 가설, 필요한 관측, 제한 예산 | 같은 동작의 반복과 다른 메커니즘 시험 |

지지나 파지 관계는 영구적인 참값으로 저장하지 않는다. 관측 시각, 근거 이미지, 재검사 조건을 붙여 이후 변형이나 슬립에 따라 갱신한다. 모델의 자신감 수치도 실제 검증을 대신하지 않는다.

로봇 운동을 비교할 때 좌표계를 맞춘다. 공개 base pose와 base 기준 grasp pose로 공간상의 grasp pose를 계산할 수 있다면 두 변환을 합성한다. 베이스가 움직인 구간에서 base 기준 Z 변화만으로 전체 파지점 이동을 설명하지 않는다. 동시에 두 파지점의 상대 자세와 천·손 관계를 확인해야 협력 조작의 효과를 해석할 수 있다.

접촉이나 힘을 직접 측정하지 못한 경우 되밀림·추종 오차·비대칭 반응은 간섭 가설의 근거로 남긴다. 특정 부품의 충돌이나 숨은 천 경로를 확정 라벨로 만들지 않는다.

## 4. 감독·복구 방법을 교체할 수 있는 구조

제어 방법과 공통 기록·평가 경계를 분리하는 방향을 검토한다. actor 단독, 사람 단독, 결정 경계의 텍스트 피드백, 사람의 직접 이어받기, 규칙 기반 감독기, 향후 학습 정책이 같은 공식 행동 계약과 기록 경로를 사용할 수 있어야 한다. 한 환경의 실제 제어원은 한 번에 하나다.

다음 조건은 실험 설정으로 다룬다.

- 정체 판단의 근거와 재관찰 방법
- 같은 파지를 유지할지, 지지가 확인된 한쪽 재파지를 비교할지
- 행동 길이와 중립·정착 방식
- 모델·사람·감독기의 제어 권한과 인계 경계
- 결정·전이·실제 시간 예산
- 점수 도달 시 마감할지, 검토 후 같은 실행을 이어갈지

`blocked`를 내면 무조건 계속하거나, 일정 횟수 뒤 무조건 종료하는 방식 모두 피한다. 현재 관측에서 시험할 다른 접근과 잔여 예산이 있는지 검토하고, 없으면 이유를 남겨 마감한다. 사용자 중지·실행 오류·입력 검증 실패·환경 한계는 의미적 정체와 별도로 처리한다.

E36은 이미 마감된 기록이다. 현재 파일에서 이어가기와 미래의 실행 중 일시 정지·재개는 다르다. 기존 prefix 재생은 새 환경에서 행동을 다시 실행하는 방법이며 정확한 천 checkpoint 복원이 아니다. 이후 구현할 제어권 전환도 현재 동작과 정착, 키 해제, 큐 처리, 새로운 관측 경계가 실제로 검증되어야 한다.

## 5. 사람 조작과 학습 자료의 활용

사람의 직접 성공·복구 시연은 다음 가설을 구분하는 후보 실험이다.

- 현재 파지에서 방향을 바꿔 진입이 되면, 같은 파지의 접근 대안이 있었음을 보여준다.
- 한쪽 재파지 후 진행되면, 파지 제약을 다르게 둔 방법을 비교할 근거가 된다.
- 사람이 실패해도 그 상태의 물리적 불가능을 증명하지는 않는다.
- 성공이 한 번 나오면 같은 원리를 다시 시험해 우연한 접촉 변화와 구분한다.

복구 이후의 좋은 동작만 추출하지 않고, 복구가 필요했던 앞 구간과 후속 결과를 함께 보존한다. 완결된 실패 에피소드 안에도 유효한 운반·정렬·관측 구간이 있을 수 있고, 최종 성공 에피소드 안에도 비효율적 반복이나 위험한 구간이 있을 수 있다. 따라서 에피소드 최종 점수를 모든 행동의 품질 라벨로 복사하지 않는다.

후속 학습 후보를 만들 때는 관측·실제 행동·다음 관측, 주체, 구간 목적, 검수 근거를 연결한다. 사후에 추정한 행동을 실제 사람 행동처럼 넣지 않는다. 원본 prefix를 반복해 사용한 구간을 독립 시연 수로 세지 않으며 E28 계열 source group과 전체 run의 의존성을 유지한다. 기술 QC, 시각 검수, 학습 승인은 별도다. 이 문서로 자동 학습을 시작하지 않는다.

## 6. 비교와 검증의 설계

한 번에 전부 바꾸기보다 질문별로 비교하되, 전체 시스템을 한 방법에 고정하지 않는다.

| 비교 질문 | 통제할 조건 | 별도 측정 |
|---|---|---|
| 종료 재검토가 도움이 되는가 | 공개 입력, 행동 계약, 총 예산 | 조기 마감, 새 접근 실행, 추가 진행, 종료 이유 |
| 수치·시각 근거 기록이 도움이 되는가 | 가능한 한 같은 출발 계보와 감독 조건 | 실제 이동 효과, 관측 불명확, 반복 정체 |
| 사람 교정이 유효한가 | 개입 전 상태의 기록, 허용 관측 | 실제 적용 행동, 개선된 관계, 재현 여부 |
| 재파지 제약이 병목인가 | 지지 확인, 변경할 파지 조건의 사전 명시 | 손 관계 보존, 지지 상실, 후속 진입 |
| critic이 유용한가 | 동일 장면·관측량과 결과 근거 | 성공 오판, 진행 누락, 판단 유보, 비용 |
| 시간이 더 필요한가 | 접근 방식과 종료 처리 | 추가 행동이 만든 관계 변화와 새 득점 |

시각 판정의 여러 모델 합의를 참값으로 사용하지 않는다. 사람 검수도 관측 근거와 불확실성을 기록해야 한다. 유효한 진행 중 종료했는지를 판단하려면 그 이후 회복 가능성을 보여주는 별도 실행이 필요하며, 화면이 좋아 보인다는 이유만으로 조기 종료를 오판으로 확정할 수 없다.

점수는 [현재 공식 평가](../../competition/EVALUATION.md)를 그대로 사용한다. 로컬 진행 지표·정착 기준·관측 안정성 창을 추가하더라도 공식 득점 조건과 별도로 명명한다. 첫 소매 항목에 새로운 유지 시간이나 시각 판정을 임의로 붙이지 않는다. 점수가 변하지 않은 구간도 조작 진단에는 유용할 수 있으나 성공 데이터로 승격하지 않는다.

## 7. 입력과 연구 범위의 경계

actor에는 지정 공개 RGB-D와 로봇 상태만 제공한다. 내부 천·접촉 기하, 평가 JSON, audit, 자유 시점은 actor·critic·행동 교사 입력으로 전달하지 않는다. 비공개 원본을 사용할 수 있는 개발자 분석은 별도 경로로 진행하며 결과를 정답 좌표나 행동 힌트로 되돌리지 않는다. 공식 결과는 허용된 평가·보상·종료 용도로 구분한다.

논문을 읽었다는 이유로 현재 PhyRC에 촉각·전류·새 접촉 센서가 있다고 설명하지 않는다. 공식 장면의 형상·물리·행동 한계·평가를 성능 개선 목적으로 바꾸지 않는다. 별도 연구 환경의 자산 생성이나 엔진 비교를 하게 되면 챌린지 실행과 분리해 목적·설정·결과를 기록한다.
