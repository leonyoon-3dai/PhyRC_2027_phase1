# 밑단 분리와 파지 대기 시간의 후속 실험안

**2026-11-13 개발자 전용 정적 소스 분석이다.** 진행 중 E28의 내부 파지 상태, 천 좌표, 면 분류, 접촉 또는 실패 원인을 조회하거나 추정한 결과가 아니다. 공식 simulator·물리·평가·진행 중 actor와 실행 프롬프트는 변경하지 않았다. 아래 내부 구현 설명은 actor 입력에 전달하지 않으며, 후속 행동 지침은 지정 RGB-D와 공개 로봇 상태만 사용한다.

**가설:** 같은 위 표면을 두 로봇이 잡고 수평으로 벌리면 한 장의 천만 팽팽해질 수 있다. 테이블과 한쪽 지지를 유지한 채 작은 들기·손목 회전으로 반대 경계를 드러내고, 필요할 때 한쪽만 다시 잡는 방식이 입구 형성에 유리할 수 있다. 파지를 명령한 뒤 실제 시뮬레이션 대기를 충분히 주는 것도 별도의 비교 항목이다. 두 가설 모두 실제 성공·득점 개선은 미검증이다.

## 소스에서 확인한 파지 선택

| 구현 사실 | 기술적 의미 |
|---|---|
| 손끝 두 점 사이 선분에서 기본 45 mm 이내인 vertex가 최소 6개인지 검사 | 단순 중심점 반경 흡착이나 실제 접촉 센서 판정이 아니다 |
| 적격 후보가 있으면 grasp center에 가까운 후보를 추가·선별 | 45 mm를 최종 부착 패치의 고정 반경으로 해석할 수 없다 |
| 단일 면 선택이 켜지고 면 분류가 있으면 가까운 6개 후보의 내부 분류로 투표하고 해당 면의 후보를 보충 | 두 로봇이 서로 반대 면을 잡는다는 제약은 없다. 각자 한 면을 잡아도 같은 면일 수 있다 |
| NativeGrasp는 선택된 후보 중 가까운 anchor를 링크 좌표계에 고정 | 기존 파지를 유지한 손목 회전은 같은 패치를 돌린다. 다른 겹으로 자동 재선택하지 않는다 |

근거: [후보 자격과 확장](../../../src/PhyRC_Sim/Env_StandAlone/Teleop_TShirt_Stretch4_Env.py#L3831), [면 투표·보충](../../../src/PhyRC_Sim/Env_StandAlone/Teleop_TShirt_Stretch4_Env.py#L3881), [native 부착](../../../src/PhyRC_Sim/Env_Config/Garment/NativeGrasp.py#L30).

주석에 남은 `SINGLE_LAYER_GAP`의 거리 간격 분리 코드는 `elif False`로 비활성이다. 이를 현재 동작으로 설명하지 않는다. 면 분류 생성에 실패하면 해당 선택도 비활성화된다. 분류가 있더라도 하나의 면은 눈에 보이는 접힌 천의 한 겹이나 밑단 입술을 의미하지 않는다. [비활성 분기](../../../src/PhyRC_Sim/Env_StandAlone/Teleop_TShirt_Stretch4_Env.py#L3912), [초기화 예외 처리](../../../src/PhyRC_Sim/Env_StandAlone/Teleop_TShirt_Stretch4_Env.py#L5032).

기본 refinement 설정에서는 후보 목표가 256개, native anchor 상한이 48개다. 이는 정적 기본값이며 현재 에피소드의 선택 vertex 수를 측정한 것이 아니다. NativeGrasp는 같은 grasp 객체가 유지되면 부착을 재생성하지 않고 PhysX가 anchor·천·접촉을 함께 푼다. 따라서 반대 입술을 선택하려면 현재 공개 관측에서 그 경계가 실제로 접근 가능해야 하며, 필요 시 허용된 open→이동→close가 있어야 한다. 내부 면 번호·정답 좌표·부착 상태를 actor에게 알려 주는 방식은 사용하지 않는다.

## 닫힘 명령과 부착 시도 사이의 시간

정책의 1전이는 0.05 시뮬레이션초이며 그 안에서 `_tick()`이 3회 실행된다. `_tick()`의 제어 간격은 1/60초다. [정책 step](../../../src/PhyRC_Sim/Policy/environment.py#L268), [제어 tick](../../../src/PhyRC_Sim/Policy/environment.py#L118).

1. open→close 의도가 바뀔 때만 toggle이 실행되고 `pending_grab=true`가 된다. 이미 닫힌 의도에 close를 반복해도 새 toggle이나 새 파지 시도가 생기지 않는다. 0 명령은 기존 의도를 유지한다. [의도 적용](../../../src/PhyRC_Sim/Policy/environment.py#L274), [의도 해석](../../../src/PhyRC_Sim/Policy/contract.py#L78), [toggle](../../../src/PhyRC_Sim/Env_StandAlone/Teleop_TShirt_Stretch4_Env.py#L3974).
2. 기본 열린 목표에서 닫힌 목표까지 `grip_pos` 명령 목표가 이동하는 시간은 0.4초다. `grip_pos`는 실제 손가락 관절 위치나 천 정지의 측정값이 아니다. [닫힘 설정](../../../src/PhyRC_Sim/Env_StandAlone/Teleop_TShirt_Stretch4_Env.py#L344), [목표 갱신](../../../src/PhyRC_Sim/Env_StandAlone/Teleop_TShirt_Stretch4_Env.py#L4692).
3. 이 목표가 닫힘 값의 0.01 이내일 때 `_settle`이 제어 tick마다 증가한다. 조건 밖이면 0으로 초기화한다. 기본 60 tick, 약 1초가 지나면 `pending_grab`을 해제하고 파지를 한 번 시도한다. 카운터 동안 근접·접촉·천 속도를 검사하지 않으며, 근접 후보 검사는 실제 시도 시점에 수행한다. [대기와 단일 시도](../../../src/PhyRC_Sim/Policy/environment.py#L124).

따라서 완전 열린 기본 목표에서 시작하면 부착 **시도**까지 명목상 약 1.4 시뮬레이션초다. 허용 오차와 이산 tick 때문에 정확히 1.400초라는 의미는 아니다. 실제 관절 추종, 천 위치와 접근 가능성에 따라 시도는 실패할 수 있으므로 이 시간을 부착 보장이나 접촉 확인으로 사용하지 않는다. 실패 시에도 pending은 해제되므로, 이미 닫힌 채 close를 반복하는 것을 재파지로 착각해서는 안 된다. 새로운 open→close는 별도 파지 변경이며 기존 시도 횟수 제한을 따른다.

## 현재 프롬프트와 자동 정착의 범위

현재 `TASK`는 모델 대기 중 물리가 멈추며 close만으로 천 부착을 가정하지 말라고 안내한다. `COORDINATED_TASK`는 “닫고 정착한 뒤 짧게 들어 천 동행을 확인”하도록 하지만 구체적인 닫힘 대기 시간은 없다. [공통·협력 지침](../../../participant/collection/codex_client.py#L44).

`post_action_settle=6`은 두 로봇 중 하나라도 앞 8개 **이동 채널**에 비영 명령을 준 `act` 뒤에만 붙는다. **gripper-only close와 중립 행동 뒤에는 이 6전이가 붙지 않는다.** 이 조건은 생성 프롬프트에도 명시되어 있다. [프롬프트](../../../participant/collection/codex_client.py#L771), [실제 적용 조건](../../../participant/collection/codex_client.py#L1262).

따라서 20전이의 close-only 명령은 1초만 진행한다. 그 뒤 바로 들기를 시작하면 기본 파지 시도가 이동 중에 이루어질 가능성이 있다. 이는 코드에서 도출한 가능성이며 E28의 특정 행동이 실패했다는 판정은 아니다. 모델 응답을 기다린 실제 시간은 이 대기에 더할 수 없다.

## 다음 시도의 행동 지침 후보 — 아직 미적용

먼저 **닫힘 대기만 바꾸는 비교**를 제안한다. 테이블 지지와 공개 관측상 안정된 배치를 유지하고, 새 close부터 작은 천 동행 시험 전까지 **총 1.5 시뮬레이션초 이상**을 명시적 행동으로 진행한다. 예를 들어 20전이 close-only 후 관측하고, 필요한 경우 기존 gripper 의도를 유지하는 10전이 중립 `act`로 총 30전이를 채운다. 한 응답의 20전이 한도를 넘기거나 모델 대기 시간을 세지 않는다. 이 수치는 기본 제어 경로에 여유를 둔 실험값이며 부착 보장은 아니다.

중립은 목표 증가를 멈출 뿐 기존 관절 목표 추종을 멈추지 않는다. 공개 관절 위치·속도·목표와 현재 영상에서 계속 움직이거나 지지가 악화되는 것이 보이면 상태를 다시 판단한다. 대기 후 짧게 움직여 해당 천 부분이 함께 따라오는지 확인하고, 확인 없이 운반하지 않는다. 이 지침은 내부 파지·면 분류를 조회할 필요가 없다.

**입구 분리 방법은 별도 비교 변수**로 남긴다.

1. 테이블에 옷 몸통을 지지하고 유용한 한쪽 파지를 anchor로 유지한다.
2. 작은 높이 차 또는 손목 pitch/roll로 한 경계를 벗겨 올려, 두 경계의 상대 움직임과 통로를 현재 여러 카메라에서 확인한다.
3. 반대 경계가 보이고 접근 가능한 경우에만 한쪽을 열고 옆·비스듬한 방향으로 재배치하여 닫는다. 다른 지지와 기존 파지 변경 횟수 제한을 유지한다.
4. 명시적 시뮬레이션 대기 뒤 짧은 차등 움직임으로 새 경계 동행을 확인하고, 관측된 입구가 유지되는 범위에서만 간격을 넓힌다.
5. 같은 천만 평평해지거나 두 번의 조정에도 관계가 바뀌지 않으면 더 당기지 않고 지지·시점·접근 방법을 재검토한다. 두 유용한 파지를 동시에 열지 않는다.

이는 기존 base·lift·arm·wrist·gripper 행동으로 가능한 실험 설계다. 실제 반대 입술 접근 가능성과 첫 손목 진입·착의 점수 개선은 미검증이다. 큰 그리퍼 간격, 검은 주름, invalid depth를 열린 통로의 증거로 사용하지 않는다.

**적용 시점은 E28 마감 이후다.** 현재 관측·행동·종료 원본을 보존하고 전수 QC·시각 검토를 마친 뒤, 유용한 닫힘 이전 경계를 골라 새 run ID의 suffix 재시도를 비교한다. 재실행은 원래 행동 prefix를 새 환경에서 수행하는 것이며 정확한 천 physics checkpoint 복원이 아니다. 직접 parent·source group·재실행/새 행동/정착 구간을 구분하고, 첫 비교에서는 대기 지침만 바꿔 효과를 분리한다. 시작점이 부적합하면 새 reset에서 비교하며 기존 성공적 동작을 덮어쓰지 않는다.
