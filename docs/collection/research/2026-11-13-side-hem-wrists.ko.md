# 2026-11-13 측면 파지·밑단 펼침 구현 검토

사용자가 수집 재개와 50점 목표의 반복 개선, 중간 과정 보존, 관찰 중 피드백 반영을 요청했다. 이 기록은 **새 시연 실행 전의 설계·CPU 검증**이다. 이 설계 작성 당시에는 E28 결과가 없었다. 이후 E28은 739전이·QC 통과·pickup 5/50점·착의 0·success=false로 마감했다. 설계와 실행 결과를 구분하며 [마감 검토](../reviews/20261113-astra-side-hem-fresh-001.ko.md)를 따른다. 현재 실행 방향은 [COLLECTION_PLAN](../../COLLECTION_PLAN.md)을 따른다.

## 바꾼 방법

기존 `coordinated-single-arm-progress`는 현재 파지를 유지하고 한 팔의 진행을 잇는 비교였다. 새 `coordinated-side-hem-wrists`는 옷의 양옆 배치부터 준비할 수 있는 별도 경로다. 로봇·손의 좌우·밑단 정체·세계 좌표를 고정하지 않고 현재 공개 RGB-D와 로봇 상태로 선택한다.

기술 가설은 **두 그리퍼 간격보다 입구의 두 경계와 방향이 먼저**라는 것이다. 같은 천을 양옆으로 당기면 입구 대신 몸판만 팽팽해질 수 있다. 작은 높이 차나 손목 방향 변화로 경계의 상대 운동을 관측한 뒤 횡방향 간격을 조절한다. 영상에서 더 어두워지거나 depth가 invalid인 것만으로 빈 통로를 인정하지 않는다. 첫 손목에 옷을 걸친 뒤에는 반대쪽 이동이 첫 손목 관계를 벗겨내지 않는지 관찰한다. 밑단 진입·손목 접촉·공식 소매 통과는 각각 구분한다.

초기 테이블 준비의 재파지는 로봇별 한 번, 배치 보정은 두 번까지다. 빈 그리퍼의 최초 파지는 재파지 횟수에 포함하지 않는다. 이는 실패한 같은 준비를 반복하는 것을 줄이려는 실험 제한이다. **전체 착의 동안 재파지를 한 번으로 막지는 않는다.** 새 진행 뒤 어깨·소매·목 작업에 필요한 변경은 첫 손목/팔 관계를 유지하는 다른 지지를 확인한 후 한쪽씩 수행한다. 변경마다 목적·관측·국소 천 동행을 다시 확인하며, 실패한 준비의 단계 이름을 바꿔 반복하지 않는다. 이 지침은 프롬프트 수준이며 실제 파지·접촉을 검사하는 자동 상태 기계가 아니다.

## 확인한 것과 남은 것

새 CLI 경로는 `exec`와 `plan-size=1`만 허용한다. 공식 행동 스키마·한계·물리·채점·actor 격리를 변경하지 않았다. 새 전략 및 이전 same-arm 관련 CPU 검사 13개를 통과했다. 그 안에는 기존 14개 전략의 56가지 입력 설정 비교, 현재 관측을 고정한 depth query, 이름 기반 행동의 실제 배열 전달, 비공개 점수·계보 정보의 actor 입력 배제가 포함된다. 기존 고정 상수 목록 검사에는 새 상수만 추가했다.

이는 코드 경로와 데이터 분리를 확인한 결과다. 실제 Astra 응답, 옷의 벌어짐, 손목 진입, 새 득점과 소스 재실행 후 물리 상태의 일치는 이 검사로 확인하지 않았다. 실제 시작점·run ID·명령·source snapshot은 환경 준비와 시각 검토 후 실행 manifest에 남긴다.

## 첫 시연에서 비교할 것

1. 새 reset과 E07/264 중 측면 접근 여유가 있는 시작점을 고른다. E27/928은 자동 선택하지 않는다.
2. 측면 배치·두 파지의 천 동행·입구 분리·첫 손목 유지의 대표 관측과 전이 번호를 보존한다. 실패해도 닫힌 원본과 로그를 덮어쓰지 않는다.
3. 첫 배치는 원점수 10을 검토 기준으로 둔다. 실제 10점 도달 여부와 `success`를 따로 기록한다. 미달이면 반복된 가림·같은 몸판 당김·지지 상실 중 관측으로 뒷받침되는 원인을 고른다.
4. 원본 마감·전수 QC·시각 검토 후 유용한 경계에서 후반 행동을 바꾼다. 앞 행동은 새 환경에서 다시 실행하므로 정확한 천 checkpoint가 아니며, 분기는 같은 source group에 남긴다.
5. 첫 손목 관계가 유지되면 반대 손목·소매·어깨·목·방향으로 진행한다. 각 후속 배치는 부모 prefix 점수보다 높은 검토 기준과 충분한 새 행동 예산을 사용한다. 50점은 목표이며 달성을 보장하지 않는다.

사용자 피드백은 run ID와 관측 경계에 연결해 실제 관측·해석·다음 변경으로 나누어 기록한다. 시연 마감 후 해당 `collection/reviews/` 기록과 시연 목록·STATUS·catalog·백업 receipt를 갱신한다. 피드백의 내부 점수·검수 좌표를 actor의 다음 입력으로 전달하지 않으며, 일반적인 조작 목표 변경은 다음 시도의 공개 프롬프트와 해시로 남긴다.
