# 목선 재파지·머리 우선 후보

**후보 코드와 CPU 검사만 완료했다. 실제 모델 호출, GPU·물리 실행, 목 통과와 득점 효과는 미검증이다.** 별도 worktree `../phyrc-neckline-candidate`, branch `experiments/neckline-first-candidate`에서 공개 기준 `75492d7e33552bb7d1461e49764300dd52212b28`을 바탕으로 준비했다. 진행 중인 E17의 실행 소스와 입력을 변경하지 않았다.

## 공개 근거와 새로운 비교점

[공개 평가 안내](../../competition/EVALUATION.md#score-items)는 목 항목을 가슴이 옷 안에 있고 머리·목이 목 입구로 나온 상태로 설명한다. 앞면 항목은 머리가 나온 상태에서 앞면 방향을 유지하는 조건이다. 두 항목에 첫 소매를 선행 조건으로 붙이지 않는다. [과제 설명](../../project/CHALLENGE_GUIDE.ko.md#2-50점은-어떻게-쌓이는가)은 실제 득점 순서가 달라지거나 여러 항목을 동시에 획득할 수 있다고 명시한다. 따라서 첫 소매를 먼저 다루는 기존 실험과 별도로 목 우선 경로를 비교할 근거가 있다. 점수 숫자나 평가 내부 판정을 후보 actor 프롬프트에 넣지 않았다.

[E15 초기 robot0 head](../assets/20261106-opening-first-partial-review/obs00000-robot_0_head.png)와 [robot1 head](../assets/20261106-opening-first-partial-review/obs00000-robot_1_head.png)에서 먼 쪽 중앙의 V형 경계가 목선 후보를 구별할 단서다. 색만으로 실제 구멍을 확정하지 않는다. [E07 운반 뒤 전체 장면](../assets/20261106-transport-waypoint/observation-00048-overview.png)은 머리·몸통·위로 든 팔을 함께 보여 준다. 현재 입력에서 목선과 연결된 몸판을 다시 확인하고, 머리 위 여유와 로봇 도달 범위를 판단해야 한다. 역사 이미지의 픽셀·좌표를 현재 목표로 고정하지 않는다.

E07·E15의 큰 공동 들기와 달리 이번 후보는 **파지 대상을 목선 근처로 바꾸고 첫 착의 대상을 손에서 머리로 바꾼다.** 확인한 E07·E10–E16 최종 결정에서 이 조합의 실행은 찾지 못했다. 단순 목선 접촉이나 앞면 방향 맞추기는 실제 머리 통과와 구분한다. 머리가 몸통 입구를 거쳐 옷 안으로 들어가 목 입구로 나오고 가슴이 몸판 안에 놓이는 경로를 목표로 하며, 이후 소매와 전체 착의를 계속할 수 있다.

## 선택과 동작 경계

새 선택지는 `--mode dressing --strategy coordinated-neckline-first --plan-size 1`이다. 다른 mode와 열린 다중 행동 계획은 시뮬레이터 시작 전에 거부한다. 모델 기본값 Astra/ultra, 기존 CLI 실행 경로와 행동 schema는 변경하지 않았다.

이 전략만 기존 기본 프롬프트의 목표 순서와 소매 협업 문장 두 곳을 별도 base에서 교체한다. 이후 `COORDINATED_TASK`, 새 `NECKLINE_TASK`, 기존 `METHOD_SATURATION_TASK`를 조합한다. `HEM_ROUTE_TASK`, `SLEEVE_TASK`, 기존 A/B 및 지지 진단 task는 붙이지 않는다. 기존 전략의 문자열과 조합은 유지한다.

- 현재 관측에서 유용한 기존 목선 파지는 보존한다. 불명확한 rim을 드러내는 작은 지지·시야 보정도 허용한다.
- 새로운 파지는 몸판의 가시적 테이블 지지를 유지하며 한 번에 한 그리퍼만 바꾼다. 파트너 파지가 불확실하면 그 불확실성을 유지한다. 두 번째 변경은 첫 새 지지를 확인한 뒤 수행한다.
- 초기 변경은 로봇당 1회, 각 짧은 배치 보정은 최대 2회다. 양쪽 국소 천 동행과 제어 가능한 목 입구를 현재 관측에서 확인한 뒤 운반한다.
- 머리·팔·입구 여유가 사라지면 뒤로 물러나거나 지지된 시야·접근을 바꾼다. 같은 가림·접힘이 실행·관측 2–3회 뒤 유지되면 속도·작은 오프셋만 계속 바꾸지 않는다.
- 닫힘, V형 색 띠, 머리 가림, 목선 접촉, 외부에서 목 구멍으로 밀기는 통과 근거가 아니다. 지지·통과 진술은 불확실성을 가진 시각적 판단이다.

이 횟수는 프롬프트 지침이며 의미를 검사하는 강제 supervisor를 추가한 것이 아니다. 실제 모델이 적절한 경계를 골라 재파지하고 지침을 지키는지는 후속 실제 실험에서 검토해야 한다.

픽셀 depth 질의는 여전히 기본 OFF다. 명시적으로 켜면 기존 제한인 exec·단일 행동·호출 timeout 최대 180초와 관측당 질의 1회/후속 1회가 적용된다. depth는 가림·의복 위상·통과 판정을 제공하지 않는다.

## CPU 검사와 검토

저장소 루트의 준비된 가상환경에서 다음 명령으로 **30개 검사 통과**했다. 실제 actor·Docker·GPU를 호출하지 않는 테스트 fixture다.

```bash
PYTHONPATH=.:tests:src/PhyRC_Sim \
  .venv/bin/python -m unittest \
  test_neckline_strategy test_regrasp_strategies \
  test_support_diagnostic_strategy test_depth_query -q
```

새 검사 6개는 목 우선 선택과 기존 행동 계약, 공개 기준의 기존 8전략 프롬프트 SHA, replay seed·계보·점수 종료값의 actor 분리, 질의 기본 OFF, ON일 때 같은 16이미지·원래 행동 schema 후속과 중간 물리 dispatch 없음, 비착의/다중 행동 거부를 다룬다. 기존 지지·재파지·depth 검사 24개도 함께 통과했다.

기존 depth OFF 회귀의 초기 1개 실패는 E17 전에 승인된 A의 table-support OR partner 문구와 pre-query 기준 `05152fa`의 문구 차이였다. 실행 oracle은 그 pre-query 기준을 유지하고 A 문자열만 고정 공개 `75492d7`에서 읽도록 보정했다. 이번 후보 프롬프트를 정답으로 복사한 것이 아니다. 별도 읽기 전용 검토에서도 기존 모든 문자열 상수 불변, 경로 지침 분리, 공개 입력 경계에 중요 결함을 발견하지 못했다.

기존 실험과 같은 조건에서 비교하려면 새 run ID와 직접 부모, 재실행 경계, 공개 입력·선택 프롬프트·실행 소스를 기록해야 한다. 이 후보의 병합과 실제 실행은 진행 실험의 종료 분석 뒤 별도로 결정한다.

E17 종료 뒤 이 후보를 루트 작업 트리에 병합하고 전체 **257개 CPU 검사(7.529초)**를 통과했다. 이전 A 지지 문구의 고정 회귀 기준도 이 통합 검사에 포함한다. 실제 목 우선 착의는 아직 실행하지 않았다.
