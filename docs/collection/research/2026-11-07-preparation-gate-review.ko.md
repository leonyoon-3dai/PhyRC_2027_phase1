# 운반 전 입구 확인 조건 · 공식 규칙과 설계 가정

**운반 전에 연속·완전한 입구를 확인하거나, 불명확하면 종료해야 한다는 조건은 공식 의무가 아니라 우리 프롬프트의 전략 가정이다.** 이 조건이 일부 시도에서 탐색을 일찍 끝냈을 가능성은 있으나, 모든 미완료의 원인이라고 단정할 수 없다. 아래는 읽기 전용 검토이며 코드 후보는 구현하지 않았다. 현재 E21을 중단하거나 프롬프트를 변경하지 않고, 변경 필요성은 종료 결과 뒤 판단한다.

근거는 로컬 [RULES](../../competition/RULES.md), [POLICY](../../competition/POLICY.md), [task 조합](../../../participant/collection/codex_client.py), E16–E20의 공개 최종 결정이다. 숨은 기하·audit·평가 내부 판정은 사용하지 않았다. E21의 최종 결과는 아직 없다. 담당자가 D2에서 아래 경계가 따로 늘어져 보이는 새 정보를 얻고 추가 lift로 관측을 이어간다고 보고했으므로, 이 메모를 현재 실험의 조기 중단 근거로 쓰지 않는다. 이 문서 작성자는 E21 관측을 별도로 판독하지 않았다.

## 공식 의무와 우리 준비 조건

| 구분 | 문서에서 확인한 내용 |
|---|---|
| 공식 허용 정보 | 지정5 RGB-D·공개 로봇 상태·과거 관측/행동을 사용하고, 그 관측으로 물체·의복 특징을 **추정**하는 모델·제어기를 허용한다. 불확실성 자체를 행동 금지 사유로 규정하지 않는다. |
| 공식 행동 경계 | 공개 관측/정식 `(2,9)` 행동과20Hz 규격, 유한값·범위·로봇 순서를 유지한다. 내부 정답·평가를 정책 입력/행동 정답에 쓰거나, adapter 밖에서 상태를 직접 조작하거나, 물리·형상·행동 한계를 바꾸면 안 된다. |
| 공식 문서에 없는 조건 | “운반 전 완전한 입구 확인”, “모든 층이 보여야 행동”, “입구 불명확 시 finish”, “배경/빈 픽셀이 보여야 입구”는 RULES/POLICY의 의무가 아니다. 짧은 탐색→재관측→복구도 별도로 금지하거나 반드시 하라고 규정하지 않는다. |
| 우리 설계 | `NECKLINE_TASK`·`OVERHEAD_TASK`는 운반 전 추적 가능한 입구를 확인하고, 제한된 준비 뒤에도 불명확하면 종료하도록 한다. A/B 및 지지 진단에도 유사한 준비·복구 조건이 있다. 이는 모델 판단을 유도하는 프롬프트 지침이며 자동 영상 판정기가 아니다. |

실제 문구는 “완전한 정답 확정”보다 **plausible / trackable** 입구를 요구한다. 그럼에도 `before carrying`와 `inconclusive → finish`가 연결되면, 모델이 부분 관측에서 입구를 더 잘 보기 위해 필요한 이동까지 선행 확인에 묶을 수 있다. 이것은 검토할 설계 위험이며 현재 코드가 논리적으로 모든 탐색을 막는다는 증명은 아니다. 공식 문서의 입력 허용을 개별 탐색 전략에 대한 주최 측 별도 승인으로 확대해서도 안 된다.

## 종료 뒤 검토할 좁은 탐색 후보

현재 유용한 지지와 대략적인 로봇·천 관계를 근거로, **완성된 개구부 확인에 앞서 관측을 얻기 위한 짧은 한 구간**을 비교할 수 있다. 전제는 과거 성공이나 정답 좌표가 아니라 새 현재 관측이다. 후보는 목선 재파지의 재권고가 아니며, 현재 유용한 몸통 경계 지지에서 검토한다.

1. **가설을 구분한다.** 예를 들어 앞쪽 패널이 이어져 막는지, 앞쪽 경계 너머 뒤 몸판이 보이는지 아직 모른다고 남긴다. 다음 작은 형태·관측면 변화가 어느 경계의 상대 움직임을 드러낼지 짧게 예측한다.
2. **이번 작은 동작의 범위를 정한다.** 현재 보이는 지지·대략적 상대 위치, 공개 목표/실측/남은 이동과 관측 가능한 방향에서 짧은 조작을 선택한다. 필요하면 작은 배치·부분 이동도 비교하되, 전체 운반 경로나 완전한 입구가 이미 확인됐다고 쓰지 않는다. 기존 정식 행동 한계·20Hz·한 구간 후 관측을 유지한다.
3. **실측과 관계를 따로 재관측한다.** 로봇이 목표를 따라 실제 움직였는지, 닫힘·잔류 운동이 섞였는지, 천 경계의 연결 또는 가림이 달라졌는지 확인한다. 변화 없는 명령과, 실제 움직였지만 정보가 늘지 않은 경우를 나눈다.
4. **복구·전환을 평가한다.** 지지 근거가 약해지거나 가림·변형이 커지면 지지된 자세·시야로 회복한다. 회복 명령은 천 상태를 정확히 되돌린다는 보증이 아니다. 새 관련 정보가 있으면 보정을 이어가고, 같은 모호함만 남으면 관측면·경계 가설을 바꾸거나 종료한다. 고정 횟수를 자동 성공·종료 기준으로 삼지 않는다.

이는 불확실성을 인정한 **정보 획득 목적의 탐색**과 이미 성립한 통과를 구분하는 비교안이다. 가려진 표면의 좌표·빈 공간·접촉을 만들어 내거나 평가를 행동 입력으로 쓰지 않는다. 더 큰 lift만 반복하는 것은 새 방법의 증거가 아니다. 기존 고정 준비 조건을 어디까지 완화할지, 실제로 더 유용한 정보·착의 진전이 생기는지는 미검증이다.

E21이 현재 경로에서 새로운 관계를 계속 드러내면 그 진전을 먼저 검토한다. 종료 뒤에도 지지 근거는 있는데 입구 준비 조건만으로 일찍 끝났다는 근거가 남을 때, 같은 계보·조건에서 준비 조건 한 가지를 바꾸는 비교를 고려한다. 재실행은 정확한 천 checkpoint 복원이 아니며 독립 성공 표본으로 세지 않는다. 지금은 문서만 남기고 실행 코드 구현·병합·추가 모델/GPU 호출은 보류한다.
