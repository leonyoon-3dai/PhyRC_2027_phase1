# 부분 관측에서 짧은 진입 탐색을 허용하는 후보

**`coordinated-entry-probe`는 불확실성 아래의 행동 선택 지침을 비교하는 미실행 후보다.** 다른 파지나 새 착의 조작의 실제 수행을 보장하는 전략으로 분류하지 않는다. 공개 기준 `eea0546f23e240867caab37fdeef3077fe46e623`에서 별도 worktree `../phyrc-entry-probe-candidate`, branch `experiments/entry-probe-candidate`로 준비했다. 활성 E21의 소스·입력·명령은 변경하지 않았고, 이번 후보의 실제 모델·GPU 실행은 없다.

## 비교 근거와 바꾸는 조건

[E19 공개 검토](../reviews/20261107-astra-entry801-named-001.ko.md)와 [실제 운동 대조](../reviews/20261107-astra-entry801-named-001-motion.ko.md)는 서로 다른 세 접근에서 실제 arm 이동과 손 가림, 복귀를 확인했다. 상방·측면 시점 변경도 실제로 수행됐다. 명령이 적용되지 않은 사례나 단순히 아무것도 하지 않고 종료한 사례가 아니다. 가림 자체로 통과를 확정하지 않는 것은 유지하면서, 유용한 지지·같은 손과 경계의 관계가 추적되는 경우 **가림을 더 구분하기 위한 한 구간의 작은 조작**을 비교한다.

[준비 조건 검토](2026-11-07-preparation-gate-review.ko.md)에 정리했듯, 모든 입구 경계가 보여야 진행할 수 있다는 조건은 공식 의무가 아니다. 공식 공개 관측·행동·물리 한계는 그대로 유지한다. 불확실성을 열린 입구나 충돌 없는 공간으로 승격하는 것도 허용하지 않는다. E21의 두 하강·가림·관측 변경·복구와 마지막 재파지는 별도 실행 결과이며, 이번 후보가 그 조작들을 모두 강제하거나 마지막 파지를 검증된 양측 출발점으로 간주하지 않는다.

## 선택과 프롬프트

`--mode dressing --strategy coordinated-entry-probe --plan-size 1`로 선택한다. 다른 mode 또는 plan-size 2/3은 출력 폴더·시뮬레이터 생성 전에 거부한다. [구현](../../../participant/collection/codex_client.py)은 신규 `ENTRY_PROBE_TASK`와 선택 분기만 추가하며, 조합은 다음과 같다.

```text
TASK + COORDINATED_TASK + ENTRY_PROBE_TASK + METHOD_SATURATION_TASK
```

기존 `SLEEVE_TASK`, `HEM_ROUTE_TASK`, A/B·목 우선·상방 task를 붙이지 않는다. 따라서 입구 가림에 대한 기존의 더 강한 전진 중단 지침이나 특정 수평/상방 경로를 동시에 요구하지 않는다. 공통 초기 협업·지지·실패 파지 복구 지침을 보존하되, 이미 유용한 현재 양측 지지는 유지하고 처음부터 열기·정렬·닫기를 반복하지 않도록 새 task에 명시한다.

독립 읽기 검토에서 공통 SATURATION의 `one-sided regrasp bound`에 대응하는 신규 task의 상한이 빠진 점을 확인했다. **이번 후보의 새 재파지 상한은0회**로 명시해 같은 grasp set에서의 탐색 선택 비교에 한정한다. 유용한 지지가 상실되면 가능한 지지된 자세·시야로 복구하고 그 한계를 남겨 종료한다. 새로운 파지 배치 비교나 초기 table 재파지 절차를 이 후보에 추가하지 않는다. 기존 다른 전략의 상한·복구 선택은 바꾸지 않았다.

- 현재와 최근 지정뷰에서 같은 손과 후보 몸통 경계의 관계를 추적한다. 손은 몸통 입구로 들어가 해당 소매로 나와야 한다. 외부에서 cuff로 거꾸로 밀기를 같은 착의로 취급하지 않으며 목선 재파지를 권고하지 않는다.
- 부분 가림은 통과 증거도 자동 종료 조건도 아니다. 손이 경계를 넘는다는 가설과 외부 몸판이 접혀 손을 가린다는 가설을 구분한다. 배경·빈 픽셀이 보여야만 입구라는 조건은 두지 않는다.
- 현재/최근 같은 손-경계 관계, 국소 천 동행으로 뒷받침되는 유용한 양측 지지, 공개 실측·최근 운동이 제한된 방향을 뒷받침할 때 **정보 획득용 act 한 번, 2–4 control steps**를 허용한다. 작은 속도는 공개 척도와 실제 반응으로 고른다. 시간만 짧다는 이유로 큰 이동을 정당화하지 않는다. 과거 관측만으로 현재 지지·여유를 확정하지 않는다.
- 다음 관측 전에 두 번째 probe를 요청하지 않는다. configured settle이 있으면 그 뒤 관측이며, probe 명령2–4전이와 중립 정착 중 잔류 운동을 구분한다. 관절 목표를 계속 누적해 포화나 파악하지 못한 잔류 운동을 보상하지 않는다.
- 지지가 약해지거나 변형·가림이 악화되거나, 포화·새 구분 정보 부재가 있으면 지지된 시야/자세 복구 또는 입구 방향·접근면 변경을 먼저 검토한다. 가려진 전진·하강을 연속 반복하지 않는다. 새 probe에는 달라진 관측 관계와 새 가설 검사가 필요하며, 속도·기간만 바꾸는 반복은 해당하지 않는다.
- 새 관계가 드러나면 그 근거로 보정하거나, 진입을 뒷받침하는 시각 근거가 생긴 뒤 같은 손을 해당 소매로 안내한다. 손이 사라짐·파란 천이 보임 자체로 입구 폐쇄·진입·성공을 선언하지 않는다. 유용한 작은 검사나 복구를 뒷받침할 근거도 없으면 미확인 이유를 남기고 종료할 수 있다.

**2–4전이는 모델 프롬프트의 probe 지침이다.** 기존 공식 action schema의 최대20전이나 물리 제한을 바꾸는 강제 제어기가 아니다. 이후 실제 기록에서 모델이 probe를 어떻게 분류·실행했는지, 그 길이와 실제 이동·잔류·지지·천 관계를 별도로 검토해야 한다. 통과나 득점 개선은 CPU 검사로 판단할 수 없다.

## 그대로 유지하는 경계

Astra/ultra·고정 CLI0.166.0 실행 경로, 공식 float32(2,9)·범위·20Hz·물리·관절 한계, 기존 검증과 dispatch는 변경하지 않는다. named와 pixel-depth-query는 기존 선택 기능이며 기본 OFF다. 기존 `include_camera_geometry`가 제공하는 공개 depth의 camera XYZ/range 경로를 그대로 사용하며 새 깊이 도구를 추가하지 않는다. depth와 과거 영상은 숨은 면·입구 정체·접촉·통과의 정답이 아니다.

공식 점수·과거 성공 라벨·내부 상태·외부 영상·좌표·정답 행동은 actor 입력에 추가하지 않는다. score는 기존 trusted 검토 종료/오프라인 출발점 선택에만 사용한다. 같은 source_group의 재생 분기를 독립 시연으로 세지 않는다.

후속 실행은 E21 마감 자료와 최종 코드 검토를 바탕으로 root가 결정한다. [검수 출발점](2026-11-07-support-startpoints-review.ko.md)의 E18/787 또는801이 비교 대상이며 정확한 천 checkpoint 복원이 아니다. 같은 검수 경계의 기존 overhead/B와 비교하더라도, 실제 조작이 같으면 새 방법 수행으로 세지 않는다. 본 문서·후보 생성 자체는 실제 시행 기록이 아니다.

## CPU 검사

신규7개 검사는 처음 실행에서 모두 통과했다(4.139초). 기존49개 전략·named·depth 회귀를 더한 **56개 집중 검사도 통과**했다. 최초56검사는10.337초였고, 독립 검토의 재파지 상한0회 보완 후 최종 문구로 다시 실행한56검사는 **11.190초**에 모두 통과했다. 실패한 검사나 실행 코드 수정으로 보정한 기대값은 없다. 명령은 다음과 같다.

```bash
PYTHONPATH=.:tests:src/PhyRC_Sim \
  /home/shadeform/workspace/PhyRC_2027_phase1/.venv/bin/python -m unittest \
  test_entry_probe_strategy test_overhead_strategy test_neckline_strategy \
  test_regrasp_strategies test_support_diagnostic_strategy \
  test_named_actions test_depth_query -q
```

[신규 검사](../../../tests/test_entry_probe_strategy.py)는 선택 task의 분리, 고정 기준의 기존 상수·`main` 이외 함수 AST 불변, **기존10전략×named ON/OFF×query ON/OFF의40조합** prompt/schema/이미지·호출·dispatch·수집 명령 동일성을 확인한다. 새 전략의 query 후속은 positional/named 양쪽에서16개 이미지·공개 시계·frozen ID를 유지한다. 합성3재생+3명령 probe+6중립 settle+예산 종료 중립1을 각각 구분하며, 질의 중 행동은 없다. 선택 기능 기본OFF·기존 action schema·trusted threshold/계보 격리와 잘못된 mode/다중 plan의 사전 거부도 검사한다.

모든 검사는 fake actor/simulator를 사용하는 CPU 검사다. 실제 CLI 호출·GPU wiring·물리·의복 행동·모델의 지침 준수·점수 개선을 검증한 것이 아니다. 기존 실행 경로를 바꾸지 않아 별도 관측 도구나 GPU 연결 시험을 추가하지 않았다.

최종 독립 읽기 검토와 root의 직접 diff 검토에서 미해결 의미 충돌은 확인되지 않았다. 전체 저장소 CPU 검사는 root 통합 단계에서 별도로 수행하며 위56개 결과와 구분한다. 후보 마감 시점에는 E21 종료·QC 완료 통보를 받았지만 이 신규 전략의 실제 실행은 아직 시작하지 않았다.
