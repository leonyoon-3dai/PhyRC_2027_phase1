# 라이브 관찰과 수집 진행 화면

기존 WebRTC 링크를 Chrome에서 새로고침하면 왼쪽 영상과 오른쪽 수집 진행 패널을 함께 볼 수 있습니다. 새 외부 포트를 추가하지 않았습니다. 자동 수집 화면의 로봇 조작·텍스트 입력은 숨겼으며 관찰 화면은 행동 모델과 별개입니다.

2026-11-06에 서버 배포와 HTTP·DOM·빌드 검증을 마쳤습니다. **교체 후 맥북 Chrome에서 실제 화면과 영상 수신이 정상인지에 대한 사용자 확인은 아직 받지 않았습니다.** 이미 연결된 클라이언트를 방해하지 않도록 추가 WebRTC 브라우저를 연결하지 않았습니다.

## 화면 읽기

| 표시 | 의미 |
|---|---|
| SDK 연결됨 | 스트리밍 SDK의 연결 성공 알림. 영상 프레임 수신 자체와는 구분 |
| 프레임 증가 확인 | 현재 브라우저가 보고한 디코딩 프레임 수 증가 |
| 최근 모델 수집 기록 | 시작 UTC와 상태로 선택한 가장 최근 모델 실행 |
| 최근 의도 단계·모델 시각 판단 | 모델의 마지막 응답. 공식 득점·성공 라벨과 별도 |
| 실제 경과·시뮬레이션 | 모델 대기 등을 포함한 실제 시간과 기록된 물리 전이 시간 |
| 공식 점수·착의 success·rate | 허용 필드만 선별한 평가 자료. 미평가·미정의 값은 미측정 |
| 기본 프롬프트·최종 행동 JSON | 펼쳐서 읽는 초기 요청문과 공개할 수 있는 최종 행동 |
| 기록 파일 | 상대 경로와 크기. 원본 파일 다운로드나 수정 기능은 없음 |

**`latest_model_collection`은 현재 영상의 실행 ID를 뜻하지 않습니다.** 모델 수집이 끝난 뒤 중립 스트리밍 측정을 실행하면 영상은 움직여도 오른쪽에는 종료된 모델 수집 기록이 남을 수 있습니다. 시작·종료 UTC와 상태를 먼저 확인합니다. 화면에도 두 실행이 같은지 확인되지 않았다는 설명을 표시합니다.

현재 E05의 `review_ready`는 첫 공식 pickup 5점 이후 과정 리뷰를 위해 종료한 상태입니다. 파일 완료·전수 기술 검사 통과·착의 success·학습 승인을 서로 구분합니다. 이 상태에서 화면이 열려 있다는 이유로 후속 파지·착의 수집을 재개하지 않습니다.

## 구현과 실행

[준비 스크립트](../../../participant/streaming/prepare_viewer.py)는 고정한 NVIDIA viewer 의존성에 [관찰 패널](../../../participant/streaming/spectator.js)을 연결합니다. 빌드 결과는 Git에서 제외한 `output/webrtc/viewer/` 아래에 생성합니다. 기존 키보드 조작 소스는 보존하지만 현재 빌드에서는 불러오지 않습니다.

저장소 루트에서 의존성이 설치된 viewer를 별도 출력 폴더로 빌드할 때:

```bash
.venv/bin/python participant/streaming/prepare_viewer.py --skip-install --out-dir dist-spectator
```

첫 설치에는 `--skip-install`을 생략합니다. 다음 명령은 선택한 빌드를 기존 8210 포트에 제공하는 [상태 서버](../../../participant/streaming/viewer_server.py)의 실행 형태입니다. 이미 서버가 실행 중이면 중복 실행하지 않고 기존 PID·명령·배포 로그를 확인한 뒤 교체합니다.

```bash
.venv/bin/python -m participant.streaming.viewer_server \
  --root . \
  --dist output/webrtc/viewer/dist-spectator \
  --port 8210
```

상태 서버 교체는 WebRTC 시뮬레이터 재시작을 요구하지 않습니다. 외부 주소·포트 매핑·접근 허용 설정은 해당 서버의 비공개 배포 기록을 따르며 공개 문서에 실제 접속 주소나 인스턴스 식별자를 넣지 않습니다.

| 경로 | 기능과 범위 |
|---|---|
| `GET /` | 선택한 viewer 빌드의 정적 파일 |
| `GET /api/progress` | 초기 프롬프트, 최근 완료 응답·행동, 선별한 상태·평가·파일 크기. `no-store` |
| `POST /api/viewer-metrics` | 최대 2KiB의 브라우저 보고. 제한된 실행 이름·숫자·불리언만 허용 |

상태 API는 완결된 JSONL 행만 사용하고 HDF5 내용은 열지 않습니다. 임의 파일 경로 API나 로봇 명령 API를 제공하지 않습니다. raw CLI 추론, 인증, 세션 ID, 내부 기하·seed, 개인 접속 주소와 절대 경로는 응답에 포함하지 않습니다. 모델의 후속 입력에도 이 상태·평가 내용을 전달하지 않습니다.

브라우저 지표는 `output/viewer-metrics/<run-id>.jsonl`에 서버 수신 UTC와 함께 저장합니다. SDK 연결, 총 프레임 수, 영상 폭·높이, 페이지 가시성을 기록하며 `client_reported`로 구분합니다. 실행 이름은 최근 모델 기록의 이름이고 `same_as_video_run_verified=false`입니다. 별도 영상 송출 측정과 연결할 때는 UTC 구간과 실제 프레임 증가를 확인해야 합니다.

## 검증 결과와 한계

관련 [CPU 테스트](../../../tests/test_streaming_viewer.py) 6개가 통과했습니다. 최신 실행 선택, 불완전 JSONL, 공개 필드 제한, 경로 탈출·심볼릭 링크·임의 API 거부, 지표 입력 제한, XSS 방지를 검사합니다. JavaScript 빌드와 모의 데이터의 로컬 Chrome 화면·DOM도 확인했습니다. 실서비스에서는 루트와 상태 API 응답, 알 수 없는 API·경로 탈출 거부, 이전 조작 화면의 제외를 확인했습니다.

캐시를 우회한 상태 생성 12회의 중앙값은 4.133ms, 최대 5.162ms였습니다. HTTP 전송·브라우저 렌더링·영상 지연을 포함하지 않은 CPU 측정입니다. [검증 상세와 원시 측정값](../reviews/20261106-spectator-ui.ko.md)에 범위와 소스 SHA256을 남겼습니다.

진행 정보는 약 1초 간격으로 조회하며 서버 캐시는 0.5초입니다. 오류 때 마지막 확인 기록을 유지하고 연결 대기 상태를 표시하므로 최신 시각도 함께 확인합니다. 브라우저가 보고한 프레임 정보는 서버의 독립 측정이 아니며, SDK 연결 성공·HTTP 요청 도착·키 입력 heartbeat만으로 실제 영상 수신을 확정하지 않습니다. 실제 영상과 모델 실행을 자동 연결하는 active-run 식별과 사람의 제어권 전환은 현재 기능에 포함하지 않습니다.
