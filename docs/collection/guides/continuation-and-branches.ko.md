# 행동 재실행과 점수 구간별 분기

첫 5점 리뷰 이후 50점까지 후속 시도를 계속하고, 점수 구간별 기록을 보존한 뒤 이전 구간에서 다른 행동을 수집하는 방향으로 진행합니다. **원본의 저장, 정확한 물리 복원, 같은 행동의 재실행은 서로 다른 기능**입니다.

정상 종료와 서버 장애 복구의 차이는 [점수 구간의 저장 내구성](milestone-durability.ko.md)에 현재 한계와 후속 계획으로 구분했습니다.

## 현재 가능한 최소 경로

종료된 E05는 공개 관측·실제 행동·다음 관측과 평가를 저장했지만 물리 엔진의 완전한 체크포인트를 저장하지 않았습니다. `raw_archive=false`이며 수집기 종료 시 환경도 닫혔습니다. 기존 사람 조작용 state slot은 입자·관절·파지 상태를 저장하지만 일부 속도·명령 이력·접촉 캐시를 초기화하고 복원 뒤 안정화 단계를 수행합니다. FEM·solver 내부 이력을 비트 단위로 복원하는 기능이 아닙니다. 원시 장면 replay는 물리를 끈 USD 상태 재생이므로 그 자체로 후속 행동을 실행하는 환경 복원도 아닙니다.

따라서 우선 **같은 초기 배치로 환경을 새로 만들고 이전의 실제 행동을 재실행한 뒤 새 공개 관측에서 후속 actor를 시작**합니다. 이 경로를 `action_replay`로 기록하고 `bitwise_physics_restored=false`를 유지합니다. 같은 행동을 사용해도 GPU 물리 결과가 완전히 같다고 가정하지 않습니다. 재실행된 관측·행동·다음 관측과 공식 평가를 새 run ID에 다시 기록합니다.

[continuation.py](../../../participant/collection/continuation.py)의 `load_replay_prefix(root, source_run_id, steps=None)`는 이 경로의 입력 검사 도구입니다. `ReplayPrefix`에는 다음 항목이 분리돼 있습니다.

| 항목 | 사용 범위 |
|---|---|
| `actions` | 읽기 전용 `float32 (T,2,9)` 실제 공개 행동 |
| `initial_public_state`, `final_public_state` | 초기·선택한 마지막 경계의 공개 관절·베이스·제어 목표·그리퍼 명령·이전 행동·시계 |
| `trusted_metadata` | 환경 reset용 seed와 정확한 원본 참조. actor·공개 manifest로 전달 금지 |
| `public_lineage` | 부모 실행, source group, 원본 해시, 선택한 전이 범위, 복원 한계. 분석 기록용 |

loader는 종료된 capture, 전수 QC 통과, 전체 검증 수, source group 일치, capture·QC의 policy SHA256과 실제 파일의 SHA256을 확인합니다. 원본 HDF5는 읽기 전용으로 열며 audit HDF5나 내부 형상 배열은 읽지 않습니다. 원본 파일이 조회 중 바뀌어도 거부합니다. seed는 신뢰된 run metadata 또는 해당 평가 결과의 metadata에서 가져오고, summary와 결과가 일치해야 합니다. 행동 관측과 함께 묶어 직렬화하지 않습니다.

`iter_action_chunks(actions, max_steps=20)`는 연속해서 완전히 같은 행동만 최대 20전이로 묶습니다. 변화하는 행동을 평균내거나 중간 전이를 생략하지 않습니다. 각 chunk의 `start_step`과 `end_step`은 원본 전이 범위입니다. 실제 환경에서는 각 0.05초 전이를 새로 기록합니다.

## E05에서 선택할 경계

E05 전체는 **253전이**이며 마지막 중립 정리 1전이도 포함합니다. 첫 pickup 5점이 기록된 경계는 **246전이·12.30초**입니다. 전체 종료 상태의 후속 시도와 최초 득점 시점의 분기는 다른 실험이므로 `source_end_step_exclusive`를 명시합니다.

재실행할 때 공식 평가를 초기 reset부터 새로 수행합니다. 원본 점수 5점을 새 결과에 복사하지 않습니다. 재실행 구간의 공식 결과와 공개 상태의 차이를 확인한 뒤 새 actor를 시작하며, 이 확인 자료와 점수는 actor 입력에 넣지 않습니다. 환경의 최대 전이 예산에는 재실행 prefix와 후속 행동을 모두 포함합니다. 최초 목표가 pickup만이었던 이전 actor의 문맥을 그대로 이어 쓰는 것과 새 착의 actor를 시작하는 것도 구분합니다.

## 구간 저장과 variation의 출처

앞으로 한 실행 안에서 점수를 얻을 때는 환경을 유지하면서 해당 `physics_tick`, 전이 경계, 누적 점수 변화와 저장된 prefix 끝을 색인합니다. 점수마다 `finish_episode`·reset을 호출하면 물리 연속 경로가 끊어지므로, 구간 색인 저장과 에피소드 종료를 분리합니다. 같은 tick에 여러 항목이 얻어지면 한 동시 획득 batch로 남기고 내부 순서를 추정하지 않습니다.

이전 구간으로 돌아가는 실험은 새 run ID와 같은 `source_group`을 사용합니다. 부모 run, 원본 에피소드·해시·전이 범위, 재실행 방법, 새 정책 시작 경계와 variation 이유를 남깁니다. 전이 출처는 `replayed_parent`, 새 `model` 행동, `supervisor_stop`으로 구분합니다. 반복된 prefix를 독립적인 신규 시연량으로 중복 집계하지 않으며, 학습·검증 분리는 source group 단위로 수행합니다. 서로 다른 분기의 성공 구간을 이어 붙여 하나의 연속 50점 시연으로 표시하지 않습니다.

loader의 합성 CPU 회귀 10개가 통과했습니다. 스트리밍 비교 실험이 종료된 후 실제 E05 원본도 읽기 전용으로 검사했습니다. policy SHA256 `f26756a867777353d99fe76a454b99c659c84886820ebdb04618f412b719d6e5`가 capture·전수 QC와 일치했고, 253개 `float32 (2,9)` 행동을 최대 20전이의 19개 chunk로 묶은 뒤 재확장한 바이트가 원본과 일치했습니다. 초기·최종 공개 상태 6개 필드의 shape와 신뢰된 seed 출처도 일치했으며 seed 값은 공개하지 않았습니다. 이 CPU 로드·검사에는 약 0.624초가 걸렸습니다.

이 검사는 재실행할 원본 입력을 확인한 것입니다. GPU 행동 재실행 결과는 별도 실행 기록으로 확인해야 하며, 정확한 FEM 체크포인트·분기 복원 시스템이 이미 완성됐다는 의미가 아닙니다.
