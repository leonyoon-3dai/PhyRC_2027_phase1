# E24 D4–D6 공개 운동 대조 · obs7까지의 부분 분석

**D4에서 robot1 팔 확장의 순증가는 실측됐고, named 행동 채널 변환 오류는 발견하지 못했다. D6의 목표 오차 감소는 주로 목표를 실측 쪽으로 올린 결과이며, 기존 수축 목표에 도달하거나 간섭을 해소했다는 증거가 아니다.** 자세 보상 뒤 그리퍼 기준점도 완전히 고정되지는 않았다.

분석 범위는 실행 중인 E24 `20261107-astra-progress1179-named-001`의 **공개 actor obs4–7·최종 D4–D6·해당 적용 구간**, 마지막 경계1317까지다. 이후 관측·최종 결과를 참조하지 않는다. [전체 수치·출처 SHA JSON](20261107-astra-progress1179-named-001-motion.json)

## 계산과 명령 경계

원본 `run_metadata.json.public_interface`의 joint names/units/action scales와 실행 당시 `source_snapshot/config/policy_interface.json`의 target 열 순서를 사용했다. arm 확장은 `arm_l1_joint`부터 `arm_l4_joint`까지, 양 로봇의 **joint_position[4:8] 합**이다. 속도는 같은 joint_velocity 네 값의 합이고, 목표는 `controller_target[1]`이다. 값이 비슷하다는 이유로 열을 추정하지 않았다.

오차의 부호는 **목표−실측**이다. 공개 `ARM_RATE=1.21m/s`·20Hz에 따른 목표 증분은 `arm action ×1.21×model steps/20`이다. 예를 들어 D4는 `−0.04×1.21×16/20=−0.03872m`다. 명령 구간과 정착 구간은 다음처럼 분리했다.

| 판단 | 모델 명령 /적용 경계 | 후속 중립 /관측 경계 |
|---|---|---|
|D4|양측 base_left+0.18·lift−0.05·arm−0.04,16전이1263→1279|configured settle6,1279→1285 /obs5|
|D5|모든 채널0,10전이1285→1295|추가 자동 settle 없음 /obs6|
|D6|양측 lift+0.045·pitch+0.05,arm r0+0.03/r1+0.13,16전이1295→1311|configured settle6,1311→1317 /obs7|

세 판단 모두 **raw named→canonical→적용 배열이 float32 기준 완전히 같다.** D4와 D6은 동시3축 명령이며 arm만의 독립 실험이 아니다. D5의0명령도 기존 target을 초기화하지 않는다.

obs4–7의 `previous_action`은 모두0이다. 특히 obs5·7은 configured settle 뒤 관측이므로 **직전 한 전이가0이었다는 기록이지, 앞선16전이까지0이었다는 뜻이 아니다.** D5는 모델이 별도로 요청한 중립10전이이며 D4의 정착6전이와 합쳐 한 명령으로 부르지 않는다.

## 팔 확장 실측·목표·속도

거리 단위는 mm, 속도는 mm/s이며 r0/r1 순서다. 속도는 경계 순간값으로, 구간 평균이나 앞으로 유지될 속도가 아니다.

- **D4,1.10초(16동작+6정착):** 목표는 양측−38.720mm 바뀌었지만 실측은 r0−37.025mm, r1 **+67.077mm**였다. r1 네 관절 각각도+10.589/+20.447/+21.391/+14.649mm 증가했다. 따라서 당시 최종 설명의 “약7cm 확장·약10cm 목표 오차”는 이 구간의 수치와 부합한다.
- **D5,0.50초(중립10):** 목표를 유지한 채 실측은 r0−0.419mm, r1−6.706mm 변했다. r1은 수축 방향으로 움직였지만98.083mm 오차가 남았다. 이것만으로 접촉·장애물이나 이후의 지속 수축을 확정하지 않는다.
- **D6,1.10초(16동작+6정착):** 목표 증분은 r0+29.040mm, r1 **+125.840mm**이고 실측 증분은+28.369/+14.273mm다. r1 오차는−98.083→+13.484mm로 바뀌었다. 목표를 크게 상향했으므로 이 감소를 이전 수축 명령의 성공으로 해석하면 안 된다. 이전 목표229.900mm와 새 실측342.256mm의 차이는 오히려112.356mm다.

각 구간의 접촉 대상이나 내부 물리 원인은 이 자료로 구별하지 않는다. D6 최종 설명의 전완 간섭 가설은 모델의 의도·추정이지 이번 수치 분석의 판정이 아니다.

## D6 위치 보상은 근사였다

D6의 양측 lift 목표는+55.440mm, pitch 목표는+0.220rad 변했다. 실제 lift는 **+52.273/+50.928mm**, 실제 pitch는 **+0.208521/+0.208447rad** 변했다. obs7에도 lift 목표 잔차+5.454/+5.403mm와 pitch 잔차+0.007988/+0.007244rad가 남는다.

세계 그리퍼 기준점은 공개 pose로 `base_world.xyz + R(base_world.wxyz 정규화) × grasp_base.xyz`를 계산했다. 아래는 D6 명령과 정착을 포함한 **obs6→7 끝점 차이**이며 경로 길이나 최대 이탈량이 아니다.

| 로봇 | grasp-base ΔXYZ(mm) | 세계 grasp 기준점 ΔXYZ(mm) | 세계 기준점 이동 크기 | base 자체 이동 크기 |
|---|---|---|---:|---:|
|r0|[−0.208,+0.032,−2.149]|[−0.183,−0.101,−2.151]|**2.161mm**|0.375mm|
|r1|[−14.993,−1.876,−3.453]|[+11.789,+3.642,−3.534]|**12.835mm**|3.290mm|

양측 실제 lift가 올랐지만 손목 회전·arm 변화와 조합돼 기준점 Z는 조금 내려갔다. r1은 r0보다 큰 위치 차이가 남는다. 이것은 **로봇 그리퍼 기준점의 근사 보상**을 검토하는 수치다. 천의 실제 파지점·접촉 위치·의복 입구 좌표를 측정하거나, 동작 내내 고정 위치를 유지했다고 입증한 것이 아니다. 목표 그리퍼 pose도 별도로 제공되지 않으므로 관절 목표를 정확한 천 위치 목표로 바꾸지 않는다.

## 출처와 제한

JSON에는 다음 출처를 남겼다.

- 현재 실행의 원본 공개 joint mapping·units·action scales, 공개 계약 target 열과 각 SHA256.
- 공개 obs4·5·6·7 원본 JSON의 SHA256·경계·clock·계산에 사용한 상태.
- 최종 decision3개와 적용 segment5개의 원본 행 번호·개행 포함 SHA256·공개 투영. active trace는 분석 시점의 **완결 행 prefix 크기/SHA**를 기록했으며 최종 파일 해시라고 부르지 않는다.
- named/canonical/applied 대조, 구간별 목표·실측 변화와 좌표계·산식.

이번에는 RGB·active HDF5·평가·audit·숨은 기하·원시 reasoning/events를 읽지 않았다. 관측1317 이후의 진행이나 공식 성공은 판단하지 않았다. 실행 코드·프롬프트·물리·데이터 원본은 변경하지 않았으며 GPU·모델 호출도 없다. 이 부분 분석을 학습 승인이나 성공/접촉 원인 라벨로 사용하지 않는다.
