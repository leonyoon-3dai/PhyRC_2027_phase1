# 관찰 전용 라이브 화면과 진행 기록

기존 WebRTC 페이지를 같은 HTTP 포트에서 관찰 전용 화면으로 교체했습니다. 왼쪽의 로봇 조작·텍스트 입력 화면을 숨기고 오른쪽에 최근 모델 수집의 프롬프트, 최종 행동 응답, 단계, 실행 ID, 기록 파일, 시간과 공식 점수를 표시합니다. 자동 수집은 계속 단일 제어원을 사용하며 이 화면에서 로봇 명령을 보내지 않습니다.

## 표시 범위와 시간의 의미

- 최근 모델 실행은 `started_at_utc`와 실행 상태를 기준으로 선택합니다. 파일 수정 시각만으로 과거 실행을 최신 실행으로 바꾸지 않습니다.
- 화면은 **최근 모델 수집 기록**임을 표시합니다. 영상 송출이 별도 측정 실행으로 바뀔 수 있으므로 현재 영상과 표시된 모델 기록이 같은 실행이라고 가정하지 않습니다.
- 단계 표시는 완료된 최근 응답·행동 기록입니다. 별도 근거 없이 모델이 현재 추론 중이라고 표시하지 않습니다.
- 공식 점수·착의 success와 모델의 시각적 판단을 따로 표시합니다. 종료된 E05는 `review_ready`, pickup 5점, 착의 `success=false`입니다.
- 프롬프트와 최종 행동의 허용 필드만 읽습니다. CLI 내부 추론, 인증, 세션 식별자, 내부 기하와 절대 경로는 표시하지 않습니다. 파일은 상대 경로와 크기만 보여주며 임의 파일 다운로드 API를 만들지 않았습니다.

브라우저의 SDK 연결 상태와 디코딩한 영상 프레임 수를 구분합니다. 연결 성공만으로 영상 수신을 확인했다고 쓰지 않습니다. 선택적으로 받은 프레임 수·크기·페이지 가시성은 `client_reported`로 표시하고 서버 수신 시각과 신선도를 함께 남깁니다. 여기에 붙는 실행 ID는 **최근 모델 수집의 이름**이며 실제 송출 실행과의 일치가 확인된 것은 아닙니다. 별도 송출 측정과 비교할 때는 시간 구간을 먼저 대조해야 합니다.

## 경계 검사와 배포 확인

상태 API는 `no-store` 응답을 사용하며 완결된 JSONL 행만 반영합니다. 정적 파일은 빌드 디렉터리 내부로 한정했고 알 수 없는 API, 임의 파일 경로 질의, 디렉터리 탈출과 외부 심볼릭 링크를 거부합니다. 브라우저 지표는 최대 2KiB의 제한된 숫자·불리언 필드만 받습니다. 원본 HDF5 내용은 상태 조회에서 열지 않습니다.

관련 CPU 테스트 6개가 통과했습니다. 최신 실행 선택, 불완전 JSONL, 공개 필드 제한, 상태 API와 경로 경계, 지표 입력 제한, `textContent` 기반 XSS 방지를 검사했습니다. 실제 JavaScript 빌드도 완료했습니다. 로컬 Chrome의 모의 데이터 화면과 DOM을 확인했으며, 이 확인은 SDK·WebRTC를 연결하지 않은 정적 점검입니다. 실제 맥북의 영상 수신을 대신하는 검사로 해석하지 않습니다.

배포에서는 기존 HTTP 프로세스의 명령을 확인한 뒤 같은 포트의 상태 서버로 교체했습니다. 루트 페이지와 상태 API의 응답, 알 수 없는 API와 경로 탈출의 거부, 빌드에서 이전 조작 UI가 빠진 것을 확인했습니다. 새 외부 포트를 만들거나 GPU 시뮬레이션을 재시작하지 않았습니다. 기존 사람 조작 소스는 삭제하지 않아 추후 별도 요청 시 복원할 수 있습니다.

## 상태 생성 비용

E05 종료 후 `review_ready` 기록을 대상으로 캐시를 우회한 상태 생성 12회를 측정했습니다. 실행 선택, 허용 필드 선별과 분리된 JSON 사본 생성의 중앙값은 **4.133ms**, 최대 **5.162ms**, 응답 JSON 크기는 **13,846bytes**였습니다. 측정 시각은 2026-11-06 04:04:15 UTC이며 개별 측정값과 소스 SHA256은 위 구조화 기록에 보존했습니다.

이 값은 HTTP 전송, 인터넷 지연, 브라우저 렌더링과 영상 지연을 포함하지 않습니다. 정상 폴링은 약 1초 간격이며 서버의 0.5초 캐시를 사용합니다. 상태 조회의 작은 CPU 비용을 확인한 결과이며, 시뮬레이션·영상 송출 성능이 개선됐다는 근거는 아닙니다.
