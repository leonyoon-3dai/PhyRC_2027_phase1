# WebRTC 관찰 ON/OFF 중립 수집 실측

[실험 계획·재현 명령](2026-11-06-streaming-benchmark-plan.ko.md) · [공개 측정값·해시](../assets/20261106-stream-operational-abba-001/metrics.json) · [수집 과정](../README.ko.md)

**이번 중립 장면에서 20 step 요청·응답 시간은 OFF 평균 20.587초, ON 평균 21.781초로 ON이 5.80% 길었습니다.** 네 과정 모두 정상 종료했고 총 260개 전이의 전체 기술 검사를 통과했습니다. 실제 브라우저 영상 프레임 증가는 확인되지 않았으므로 이 수치를 원격 시청 중 비용으로 표시하지 않습니다. 모델 호출이 없는 실험이므로 전체 Astra 수집 loop의 속도 차이도 아닙니다.

## 실행 조건과 범위

- 비교 ID: `20261106-stream-operational-abba-001`
- 실행 시각: 2026-11-06 04:08:11~04:17:14 UTC
- 순서: OFF → ON → ON → OFF, 조건당 독립 프로세스 2개
- 각 과정: 중립 행동 warmup 5 step → 요청 없는 10 wall초 대기 → 중립 행동 20 step × 3 → 정상 finish
- 저장량: 과정당 65전이·3.25 simulation초, 전체 260전이·13 simulation초. 실제 시간 비교에 사용한 전이는 warmup을 뺀 240개
- 동일 조건: 공식 환경·물리·평가·행동 범위, 공개 카메라 5개·256×256 RGB-D, 20 Hz simulation cadence의 HDF5 기록, 초기 배치 고정
- 모델 호출: 0회. `source=integration_test`, 학습 승인 상태 `unreviewed`

기존 운영 경로의 `--webrtc` 전체를 비교했습니다. ON에는 SDK, 앱 UI 표시, 관찰 endpoint, 대기 중 렌더링이 함께 들어갑니다. OFF도 공개 RGB-D 센서 렌더링과 저장은 그대로 수행합니다. 두 조건의 앱 기본 크기는 1280×720이며, 선택형 viewport 보정이나 SDK만 분리하는 추가 실험은 실행하지 않았습니다.

과거 배치·practice 환경 override를 제거하고 같은 고정 배치를 사용했습니다. 기존 비공개 송출 환경만 전달했으며 포트·방화벽을 변경하지 않았습니다. GPU 비교 구간에는 다른 과제 수집·모델 호출·GIF 인코딩을 병행하지 않았습니다. 각 과정의 HDF5 전체 검사는 네 번의 시간 측정이 모두 끝난 뒤 수행했습니다.

render 횟수와 시간은 명시적 10초 창뿐 아니라 **collector의 모든 요청 대기 구간 누계**입니다. 따라서 ON의 4.8초를 정확한 10초 창의 GPU 점유 시간이나 모델 대기 비용으로 바꾸어 쓰지 않습니다. OFF에서는 대기 중 render를 하지 않았고 ON에서는 render 전후 물리 시계 불변을 검사했습니다. 별도의 CPU·GPU·NVENC 사용률이나 장치 전력은 측정하지 않았습니다.

## 브라우저 수신의 확인 한계

같은 서버 수신 UTC 구간으로 viewer telemetry를 대조했습니다. 네 과정에 대응하는 샘플 수는 각각 45·25·26·32개로 총 128개였습니다. 모든 샘플에서 SDK 연결 bool, 프레임 증가 bool, 페이지 표시 bool은 false였습니다. 실제 영상 수신을 확인할 근거가 없으므로 `viewer_connection_status=unverified`를 유지합니다.

telemetry의 run label은 이전 모델 수집 ID를 가리켰고 `same_as_video_run_verified=false`였습니다. 따라서 이번 비교와는 시간창으로만 연결했으며, 그 run label이 실제 송출 scene의 정체성을 증명한다고 취급하지 않았습니다. 포트가 열렸거나 상태 보고가 도착했다는 사실만으로 시청 중이라고 판단하지 않습니다.

이번 결과는 **실제 영상 수신이 검증되지 않은 상태에서 운영 송출 기능을 켠 비용**입니다. 시청 client가 연결되어 프레임이 계속 증가할 때의 NVENC·전송·렌더링 비용은 별도 비교가 필요합니다. 실제 수신을 측정할 때는 기존 Mac Chrome 한 client를 사용하고 시간창별 연결 상태·영상 크기·프레임 증가를 함께 남깁니다.

## 기록 검수와 다음 판단

`validate_capture`는 4개 child 모두 65/65전이를 검사했습니다. 파일 SHA, episode 완료, 공개 관측 형식, 실제 행동과 previous action, 0.05초 간격·12 physics tick 연속성, 관측 연속성, 유한값, 종료 표지, 평가 라벨 정합성을 통과했습니다. 기술 검수 통과는 과제 성공이나 학습 사용 승인이 아닙니다.

원본은 `output/stream-benchmarks/20261106-stream-operational-abba-001/`와 각 `output/collections/20261106-stream-operational-abba-001-NN-on|off/`에 보존했습니다. 실패 로그를 덮어쓴 재시도는 없으며, 정상 로그·공식 평가·HDF5·외부 QC를 그대로 유지했습니다. 공개 JSON에는 선별한 시간·QC·파일 해시·소스 해시와 viewer 집계만 포함합니다. 비공개 접속 주소, 인증·원시 네트워크 정보는 포함하지 않습니다.

소스 검토에서 후속 작업에 따른 변경도 확인했습니다. 마지막 OFF의 Kit 시작 로그는 04:15:02 UTC이며, collector에 선택형 reset seed 인자를 추가한 파일 수정 시각은 04:15:12 UTC입니다. collector 모듈은 Kit를 시작하기 전에 읽으므로 마지막 과정도 수정 전 코드로 시작했다는 순서상의 근거가 있습니다. 별도 reload는 없었고 벤치 명령에 새 옵션을 사용하지 않았습니다. 프로세스가 자체 출력한 collector hash는 없으므로 이 확인 방법을 직접적인 런타임 hash 측정과 구분합니다. 시작 시 기록한 SHA와 일치하는 소스 8개를 별도 snapshot으로 보존했고, 공식 환경·센서 소스 hash는 네 과정 모두 같았습니다.

이번 회고를 반영해 후속 비교에서는 전체 조건이 끝날 때까지 실행 소스 변경을 미루고, 각 child 시작 시 소스 hash를 따로 남기는 방식이 적절합니다. 이번 측정은 이력과 위 확인 한계를 보존하며 소급해서 깨끗한 소스 고정 실험으로 다시 표시하지 않습니다.

운영 판단으로는 이번 조건에서 ON의 추가 비용이 관측됐고, 실제 시청 중 비용은 아직 남아 있습니다. 5.80%를 모든 장면의 일정한 손실로 가정하거나, OFF로 바꾸면 전체 AI 수집이 같은 비율만큼 빨라진다고 계산하지 않습니다. 후속 비교가 필요하다면 **실제 영상 수신을 검증한 같은 중립 ABBA**를 우선하고, UI 표시·idle render·SDK 비용을 분리하는 실험은 별도 변경으로 진행합니다.
