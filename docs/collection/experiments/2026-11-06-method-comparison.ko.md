## E01: 계측을 먼저 바로잡기

이번 단계의 목적은 성능 주장을 하기 전에 비교할 수 있는 측정값을 만드는 것입니다. 작업 코드의 사용량 집계는 thread별 누계와 증가분, 중복·역행·누락·실패 호출을 구분합니다. CPU 검사는 누계가 같은 이벤트, 다른 thread와 재개, 역행 값, 사용량이 없는 중단, 사용량은 반환됐지만 행동이 거부된 호출을 다룹니다. 실제 모델 호출의 전체 청구 사용량이 항상 복원된다고 가정하지 않습니다.

actor 호출의 추가 계측은 현재 다음 세 구간입니다.

| 필드 | 측정 범위 | 해석 한계 |
|---|---|---|
| `staging_wall_s` | 공개 입력 파일 준비부터 프로세스 실행 직전까지 | 모델이 처리한 시간 아님 |
| `process_wall_s` | CLI 프로세스 실행 구간 | Docker/CLI·네트워크·서비스 대기·추론·응답이 섞임 |
| `result_parse_wall_s` | 완료 이벤트와 최종 결과 해석 | 응답을 받기 전 모델 처리 시간 아님 |

`completed`와 미확정 구간도 함께 보존합니다. 이 분해만으로 첫 응답 시각이나 모델 내부 시간을 알 수 있는 것은 아닙니다. 중단·누락 처리의 CPU 검사와 실제 정상 호출의 계측 확인을 구분합니다.

## E02: 상주 호출 연결 시험 보류

같은 격리 경계 안에서 App Server 프로세스를 유지하고 빨강→초록 합성 이미지 2턴을 처리하는 연결 시험을 시도했습니다. **r1~r5의 승인 응답은 0개**입니다. 실제 `turn/start` 요청 시도는 총 3회였으며 모두 첫 턴 완료를 승인하기 전에 끝나 두 번째 이미지 호출은 실행하지 못했습니다. [시도별 원인·검증·보존 기록](2026-11-06-app-server-probe.ko.md)

문제는 새 어댑터의 시작 안내·thread/turn 알림 분류와 호환성입니다. r5에서는 기대한 첫 JSON과 사용량 알림을 받았지만 완료 이벤트를 확인하기 전에 실패했습니다. 이를 응답 승인·2턴 기억 시험 통과로 바꾸어 표시하지 않습니다. 요청 시도 횟수는 청구된 추론 횟수와 구분합니다.

CPU 프로토콜 검사가 통과했어도 실제 이미지 2턴과 정상 정리가 함께 검증된 수집 경로는 아닙니다. 추가 호환성 확인은 보류하고 기존 CLI `exec/resume` 경로로 E03을 진행합니다. 실패까지 걸린 짧은 시간을 정상 응답 지연이나 속도 개선의 근거로 사용하지 않습니다.

## E04: 픽업 목표·최대 2구간 탐색 실행 중

`20261106-astra-pickup-plan2-001`을 시작했습니다. `gpt-6-astra`·`ultra`와 CLI `exec`를 유지하며 `mode=pickup`, 한 응답 최대 2구간·계획당 최대 20 step, 전체 최대 24구간·600 step, 호출 timeout 180초를 사용합니다. 공식 누적 5점 감시는 행동 문맥 밖에서 현재 행동 응답 경계의 종료·리뷰만 담당합니다.

이전 시도 연결은 `parent_attempt=20261106-astra-dressing-001`, 출처 그룹은 `20261106-astra-pickup-methods`입니다. 이전의 완전 착의 목표에서 픽업 목표로 프롬프트도 바뀌었으므로 E00 대비 속도 개선의 인과 비교가 아닌 탐색 실험입니다. **최종 점수·성공·전수 검사 결과는 아직 확인 전**이며 실패·재시도·미실행 계획도 보존합니다.

## 공통 비교와 기록 원칙

- **유지할 조건:** Astra·ultra, 지정 공개 관측, 공식 행동 제한과 물리·평가 정의. 모델/effort·카메라·시작 조건·제어 방식까지 동시에 바꾸지 않습니다.
- **분리할 시간:** 전체 벽시계, actor 구간, 환경 요청·응답, 실제 시뮬레이션 시간. 서로 다른 범위의 값을 더하거나 같은 지표로 취급하지 않습니다.
- **보존할 과정:** 원본 프롬프트, 최종 계획·행동 JSON과 짧은 행동 설명, 공개 이미지, 실제 행동·전이, 실패·재시도·종료, 사용량의 확인·미확정 범위. 숨겨진 추론은 공개하지 않습니다.
- **보존할 출처:** 새 run ID, 실제 소스와 변경 상태, 모델·CLI·이미지 식별자, 원본 SHA-256. 동일 복원 출처의 재시도는 source group으로 연결하고 기존 기록을 덮어쓰지 않습니다.
- **판정할 결과:** 파일 완료·전수 기술 검사·학습 승인·공식 점수·착의 success를 별도로 기록합니다. 같은 physics tick의 여러 점수 획득은 한 동시 batch로 남깁니다.
- **공유할 중간 상태:** 계획, 구현, CPU 검사, 실제 모델 연결, GPU 연결, 과제 시도를 구분해 자주 기록합니다. 실패를 성공 결과가 나올 때까지 숨기지 않습니다.

첫 공식 누적 5점의 감시는 행동 문맥 밖에서 수행합니다. 조건을 만족하면 현재 행동 응답 경계에서 종료 후 사용자와 과정을 리뷰합니다. 이 감시 조건을 모델이나 로컬 제어기에 점수 피드백을 제공하는 경로로 사용하지 않습니다.
