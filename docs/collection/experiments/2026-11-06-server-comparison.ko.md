# 2026-11-06 서버·수집 경로별 속도 비교

[수집 과정 목차](../README.ko.md) · [선별 측정값·원본 SHA-256](2026-11-06-server-comparison.json) · [방법별 실험 기록](2026-11-06-method-comparison.ko.md)

**현재 L40S의 사람 조작용 라이브 실행은 simulation 1초당 약 9.57 wall초로, 과거 기존 L40S 표본과 비슷합니다.** 11월 3일 다른 L40S의 사람 조작 표본은 약 8.70 wall초였으며, 현재 주 표본보다 처리량이 약 9.95% 높았습니다. 현재 AI 수집의 더 긴 시간에는 즉시 센서 저장·평가와 모델 호출이 함께 들어 있으므로 이 숫자만으로 서버 하드웨어가 느려졌다고 판단할 수 없습니다.

이 문서는 보존된 실행 이력과 오늘의 측정값을 비교합니다. CPU·드라이버·작업 경로·시작 상태·동시 부하를 통제한 하드웨어 반복 실험은 아닙니다.

## 지표와 현재 장비

`RTF = 진행한 simulation초 / 경과한 wall초`입니다. RTF가 높을수록 같은 실제 시간에 물리가 더 많이 진행됩니다. 역수 `wall초 / simulation초`는 simulation 1초를 진행하는 데 걸린 실제 시간이며 낮을수록 빠릅니다. 브라우저 영상 FPS나 키 입력 응답 시간, 순수 GPU kernel 성능과는 다른 지표입니다.

| 현재 서버에서 직접 확인한 항목 | 값 |
|---|---|
| GPU·메모리 | NVIDIA L40S · 46,068MiB |
| 드라이버 | 580.126.09 |
| CPU·할당 | Intel Xeon Platinum 8452Y · 12 vCPU |
| 호스트 RAM | 약 70.8GiB |

GPU 정보는 `nvidia-smi`, CPU는 `lscpu`, RAM은 `/proc/meminfo`에서 확인했습니다. 조회 시각과 선별 결과는 [측정 JSON](2026-11-06-server-comparison.json)의 `hardware_current`에 있습니다. 장비 이름이나 vCPU 개수만으로 속도 차이의 원인을 확정하지 않습니다.

10월 26일 값은 [기존 구간별 측정 JSON](../../project/sessions/20261026-runtime-components.json)의 `1280-recording` 조건입니다. 오늘 주 표본과의 RTF 차이는 수치상 약 +0.036%이지만, 날짜와 표본 길이가 달라 동등성 검증 결과로 해석하지 않습니다. [당시 측정 범위와 한계](../../project/PERFORMANCE.ko.md)

11월 3일 서버는 **EPYC 9254·8 vCPU·RAM 약 144GiB·L40S**였습니다. 표에는 그날 `human-relay`의 누적값을 사용했습니다. 같은 문서의 짧은 중립 진단·브라우저 미연결 진단과 섞지 않았습니다. [11월 3일 측정 JSON](../../project/sessions/20261103-runtime-summary.json)

현재 주 표본을 기준으로 계산하면 다음과 같습니다.

```text
처리량 증가 = (0.114918571883 / 0.104521070789 - 1) × 100 ≈ 9.95%
같은 simulation 시간의 wall 감소 = (1 - 0.104521070789 / 0.114918571883) × 100 ≈ 9.05%
```

따라서 “처리량이 약 10% 높다”와 “걸리는 시간이 10% 짧다”를 같은 숫자로 쓰지 않습니다. 이 비율은 두 보존 표본의 비교이며 새 서버를 사용했을 때 모든 과제·정책이 같은 비율로 빨라진다는 예측이 아닙니다.

A10은 드라이버 `570.148.08`의 검사 우회와 화면 노이즈가 함께 기록된 환경입니다. 0.054는 당시 근사값이며 L40S와 조건을 맞춘 결과가 아닙니다. GPU 모델만의 효과를 산출하거나 현재 A10의 일반 성능으로 확대하지 않습니다. [A10 당시 기록](../../project/sessions/20261103-a10-to-l40s.ko.md)

## 오늘 라이브 측정의 선별·합산 방법

두 원본 `performance.jsonl`에서 아래 조건을 모두 만족하는 창을 선택했습니다.

```text
simulation_time_s > 1
reset_detected == false
window_wall_s > 0
simulation_dt_s가 존재하고 0 이상
선별된 수치가 모두 유한함
```

주 표본은 `output/sessions/20261106-webrtc-live-ip/performance.jsonl`의 186개 기록 중 182개입니다. 합계는 wall **925.969640863초**, simulation **96.783338381초**입니다. 보조 표본은 `output/sessions/20261106-webrtc-live/performance.jsonl`의 104개 기록 중 101개이며 wall **513.266629166초**, simulation **54.216669494초**입니다.

개별 창의 RTF를 단순 평균하지 않고 **전체 simulation 증가량의 합을 전체 wall 시간의 합으로 나눴습니다.** 원본 위치는 로컬 보존 경로이며 GitHub 다운로드 링크가 아닙니다. 원시 로그 전체는 게시하지 않고 [선별 숫자 JSON](2026-11-06-server-comparison.json)에 원본 SHA-256, 제외 행, 선택한 창의 행 번호·wall·simulation 증가량·simulation 시각만 넣었습니다. 공개된 숫자로 두 합계와 비율을 다시 계산할 수 있습니다.

두 로그의 모드는 `human_stream_no_policy_inference`입니다. 모델 판단 지연이 포함된 AI 수집 속도로 부르지 않습니다. 클라이언트 연결 상태·사람 입력·전송 부하를 모든 시점에 고정한 비교도 아닙니다.

## AI 수집 E04가 더 느리게 보이는 이유

E04 `20261106-astra-pickup-plan2-001`은 **공개 5카메라 RGB-D를 즉시 읽고 20Hz HDF5에 기록하며 공식 평가를 함께 실행하는 경로**입니다. 사람용 archive·deferred 렌더 경로와 작업량이 다릅니다. [E04 공개 manifest](../attempts/20261106-astra-pickup-plan2-001/manifest.json) · [시도 기록](../attempts/20261106-astra-pickup-plan2-001/README.ko.md)

| E04의 측정 범위 | wall 시간 | simulation 1초당 환산 |
|---|---:|---:|
| 환경 요청·응답 합계 | 181.916712초 | **21.6568초** |
| actor 호출 합계 | 337.250354초 | 모델 대기 중 물리 정지 |
| 전체 실행 | 582.025450초 | **69.2887초** |
| 저장된 실제 진행 | 168전이 · 8.4 simulation초 | 20Hz |

환경 요청·응답에는 행동 전달, 물리 진행, 센서 읽기, 직렬화·저장과 평가가 함께 들어 있습니다. **21.66초를 순수 물리 계산 시간으로 부르지 않습니다.** 전체 69.29초에는 모델 호출과 초기화·종료 등 다른 처리도 포함됩니다. actor와 환경 구간 합계를 뺀 나머지는 약 62.86초이며 이를 단일 원인의 비용으로 배정하지 않습니다.

모델이 기다리는 동안 simulation clock이 진행하지 않으므로 전체 실행을 simulation 시간으로 나누면 큰 값이 나옵니다. 사람용 주 표본의 9.57초와 E04 환경의 21.66초, E04 전체의 69.29초는 각각 다른 범위입니다. 이 차이를 서버 자체의 하락률로 계산하거나 센서·기록을 끄면 그대로 회복된다고 예측하지 않습니다.

## 해석의 한계와 다음 비교

- 과거 10월 진단은 조건당 한 번의 짧은 표본이며 CPU 영상 인코딩이 동시에 실행됐습니다. 오늘의 GIF 변환 같은 동시 작업도 통제된 비교에서는 별도로 배제하거나 기록해야 합니다.
- CPU·RAM·드라이버·소스 버전, 시작 장면, 관측·평가·기록 경로, 브라우저 연결 조건이 모두 일치하지 않습니다. 현재 자료만으로 CPU, GPU, 렌더링 또는 WebRTC 하나의 기여도를 확정하지 않습니다.
- WebRTC ON/OFF 비교에서도 공개 RGB-D와 HDF5 기록, 평가·행동 예산을 유지하고 초기화·행동 실행·대기 렌더 시간을 나눠야 합니다. [별도의 스트리밍 비교 계획](2026-11-06-streaming-benchmark-plan.ko.md)
- 시간당 가격은 새로 조회하지 않았고 과거 문서의 가격을 현재 가격으로 재사용하지 않았습니다. 이 기록에는 가격 추정이나 서버 비용 비교를 포함하지 않습니다.

현재 자료가 뒷받침하는 것은 **기존 L40S의 사람용 실행이 과거 같은 계열의 표본과 비슷한 속도이며, 11월 3일 다른 구성의 L40S 표본이 약 10% 높은 처리량을 보였다는 것**입니다. AI 수집의 속도를 개선할 때는 서버 차이와 함께 관측·저장·평가·모델 호출의 실제 비용을 각각 확인합니다.
