## 검토할 기록

- **시연 29–32** · 동일 슬롯으로 네 번 시작했습니다. 30부터 경로가 분명할 때 12–20전이 동작을 적용했습니다. 31에서 첫 노란 밑단 파지점을 두 카메라로 확인하도록 구체화했고, 32가 같은 프롬프트로 반복했습니다.
- **시연 32 종료 관측** · 노란 끝 주변에서 턱이 닫혔고, 실제 물림 위치와 소매 통과는 가림으로 미확인이었습니다.
- **시작점 비교** · 시연 28의 299전이 슬롯은 29–32의 공통 출발점입니다. 다른 종료 슬롯을 선택하면 새 조건으로 기록하고, 정착 후 0전이 장면을 비교합니다.
- **저장과 평가** · 슬롯은 로컬 연구용 근사 저장입니다. 공식 제출은 주최 측 초기화와 공개 관측·행동 규격을 따릅니다. [챌린지 규정](../competition/RULES.md)

- **[시연 26–32 비공개 백업 확인서](20261126-demo26-32-private-backup.json).** 원본, 검토 ZIP, 프레임, 저널, 종료 슬롯과 실행 환경 자료 44개를 고정 revision에서 검증했습니다. 검토 클립 258개와 JPEG 복원도 확인했습니다.

1. 저장소를 받고 [환경 준비](start.md)에서 GPU와 CLI를 확인합니다. Hugging Face 비공개 백업은 소유 계정으로 인증합니다.
2. 백업 확인서의 고정 revision과 SHA-256으로 필요한 회차를 검증합니다. 아래 명령은 저널·검토 클립·JPEG를 비어 있는 출력 경로에 복원합니다.
3. 시작 슬롯을 선택한 경우, 저장 확인서와 슬롯을 원래 경로에 함께 놓고 복원·정착 뒤 공개 관측으로 상태를 확인합니다. 새 시연은 복원 시점 이후를 0전이로 기록합니다.


```bash
python3.12 scripts/restore_review_gallery.py \
  --receipt docs/active/20261126-demo26-32-private-backup.json \
  --frames-destination output/operator-traces
```

- **원본 수집 자료** · 확인서의 `runs[].archive`에서 경로를 고르고 `hf download`에 저장소 ID, `--repo-type dataset`, 고정 `--revision`을 지정합니다. SHA-256을 확인한 뒤 `python3.12 participant/ops/artifacts.py restore <새 폴더> --archive <파일>`로 압축을 풉니다. 기존 저널이나 수집 데이터와 합칠 때는 회차별 경로를 대조합니다.
- **당시 실행 구성** · 확인서의 `operations` 묶음에 패치, 프롬프트, 실행기와 `runtime.json`이 있습니다. 체크포인트에서 GPT 자동 수집을 재구성할 경우 패치의 안내와 기본 커밋을 확인하고 `git apply --check isolated-runtime.patch`를 통과한 새 체크아웃에 적용합니다. 실행기는 당시 조건을 기록한 자료입니다.
