# 11월 24일 시연 4 실행 전 인계 기록

시연 4와 후속 시연 5·6은 종료됐다. 아래 내용은 당시의 조건과 실행 기록을 대조할 때 사용한다. 현재 서버 인계와 여섯 회차의 복원 방법은 [새 서버 준비](start.md)를 따른다.

**다음 회차는 시연 4, 새 장면의 0전이에서 시작하는 독립된 GPT 단독 시연이다.** 시연 3은 608전이에서 사용자의 종료 요청으로 마쳤고, 유효 원점수는 픽업 5/50점이다. 시연 2의 20/50점이 세 회차 중 최고다. 50점과 착의 성공은 다음 실험의 목표다. [세 시연의 실패와 복구 구간](20261123-recovery-review.ko.md)

새 서버에서 사용자에게 필요한 첫 지시는 **“이 저장소의 시연 4 인계에 따라 시작해주세요”**이다. 아래 명령은 서버에 연결한 Codex 또는 운영자가 실행한다. 11월 23일 마감 작업에서 시연 4의 물리·모델 실행은 시작하지 않았다.

## 무엇을 검증할 것인가

**첫 판별 장면은 공중에 들린 셔츠를 어깨로 보내기 직전이다.** 시연 3의 281–301전이에는 옷이 양쪽 전완을 가로질렀지만 먼 손목은 가려졌다. 다음 12전이에 R0·R1 집게가 각각 18.2·17.0cm 전진하자 한 손이 파란 겉감 위에 보였다. 처음부터 밖에 있었는지, 당길 때 빠졌는지는 미확인이다. 시연 2의 2111–2138전이에는 R1 집게가 약 5.3cm 올라가도 정수리 근처 목둘레가 거의 움직이지 않았다. [두 실패 장면과 클립 번호](20261123-recovery-review.ko.md)

| 단계 | 작은 동작과 다음 관측에서 확인할 것 | 가려지거나 의도와 다른 효과가 보일 때 |
|---|---|---|
| 밑단 열기와 운반 | 테이블이 몸판을 받칠 때 한 집게는 지지하고 다른 집게는 노란 자유 가장자리 한 겹을 든다. 반대쪽 경계와 파란 안쪽 면이 따로 보이고 들어 올린 뒤에도 입구가 유지되면 양손 앞으로 운반한다. | 두 겹이 함께 따라오면 한쪽을 테이블에 다시 받쳐 장력을 풀고 다른 가장자리를 잡는다. 공식 양면 영상 19.5–20초의 후면에서 손끝을 향해 열린 타원을 확인할 수 있다. |
| 양손목에 걸친 뒤 지지 확인 | 같은 손끝에서 손목까지 따라가며 가까운 밑단과 먼 밑단이 손의 어느 쪽에 놓였는지 두 손 각각 확인한다. 한 로봇이 천을 받친 채 다른 쪽만 2–4전이 짧게 조정한다. 새 관측에서도 **두 전완에 각각 걸려 있고 지지 쪽 손도 빠지지 않았을 때** 목으로 진행한다. | 손목 카메라가 집게 하우징에 가리면 반대쪽 헤드와 전체 뷰에서 먼저 찾는다. 한 주먹이 겉감 위로 나오면 남은 쪽에 여유를 주고 놓친 쪽 밑단을 손끝 앞으로 되돌린다. 같은 주먹이 다시 보이면 집게의 실제 이동 방향을 확인하고 접근각 또는 파지점 한 가지를 바꾼다. 양쪽이 빠졌으면 입구부터 다시 연다. |
| 목둘레 통과와 어깨 안착 | 양팔의 걸침을 유지하며 파란 몸판에서 V넥과 이어지는 테두리를 짚는다. 한쪽을 받치고 다른 쪽을 조금 들어 **그 테두리가 정수리에 대해 움직이는지** 본다. 따라오면 정수리 너머로 넘겨 뒤쪽 천을 어깨에 내린다. 얼굴이 목둘레 밖에 드러나고 몸판이 가슴 앞, 어깨 천이 양쪽에 놓였는지 확인한다. | 주름만 펴지면 당김을 풀고 다른 손으로 식별 가능한 목둘레 인접 가장자리를 다시 잡는다. 지지하던 손목이 빠지면 그쪽부터 복구한다. 원본의 21.5–30초는 가림이 있어 손과 머리가 빠져나오는 세부 순서는 실험 가설로 둔다. |
| 두 소매와 최종 자세 | 팔마다 해당 소매 끝을 따라가 손끝과 손목이 **서로 다른 출구 밖**에 보이는지 확인한다. 위팔과 어깨 천을 한쪽씩 정리하며 반대 손과 목둘레를 다시 본다. 공식 영상 32–35.8초처럼 얼굴과 양팔이 보이고 V넥은 앞, 노란 밑단은 허리에 남는지 관찰한다. | 한쪽 손이 몸판 속에 남으면 확인된 소매와 목둘레는 받쳐 두고 남은 소매에 여유를 준다. 감독은 항목별 첫 득점 시각과 마지막 유지 상태를 함께 읽는다. 시연 2는 왼쪽 위팔 점수를 얻은 뒤 종료 자세에서 그 팔이 빠졌다. |

위의 시간은 [공식 전후면 영상](https://github.com/rirolab/PhyRC_2027_Challenge/blob/9afd513e926a82f1866a4b870135e33faba1358e/docs/videos/Front_Back_8x.mp4)의 재생 시각이다. ## 새 서버에서 시작하기

1. [서버 준비 1–2절](start.md#1-환경-준비)에 따라 현재 GitHub `main`을 clone하고 Docker GPU, 에셋, Python 환경, FFmpeg와 고정 Codex CLI를 준비한다. 연결이 끊겨도 수집을 유지할 `tmux`도 준비한다. 모델 권한은 새 서버에서 별도로 확인한다. 비교를 위해 시드 43, 테이블 인덱스 2, 셔츠–마네킹 마찰 0.35를 유지한다.
2. GPU smoke와 별도 ID의 모델 연결 검사를 마친 뒤 해당 프로세스의 종료를 확인한다. 시연 4에는 저장 슬롯이나 이전 행동 prefix를 지정하지 않는다. 이전 영상이 필요하면 [지난 구간의 새 서버 복원 절차](20261123-demonstrations.ko.md#지난-구간을-새-서버에서-열기)와 [비공개 백업 목록](20261123-private-backup.json)을 사용한다. 원본 데이터 복원은 새 reset과 독립적이다.
3. 새 Jupyter 서버의 파일 루트와 외부 Brev 접속 주소를 확인한다. 당일 서버는 파일 루트가 사용자 홈이었다. 아래 `phyrc_view_root`는 새 서버의 실제 파일 루트로 설정한다. 같은 이름의 tmux 세션이 있으면 먼저 이 저장소의 프로세스인지 확인한다.

```bash
# 새 clone의 루트에서 실행한다.
phyrc_view_root="$HOME"
tmux has-session -t phyrc-review 2>/dev/null || \
  tmux new-session -d -s phyrc-review -c "$PWD" \
    .venv/bin/python tools/segment_review.py --root output/segment-review serve --port 8765
tmux has-session -t phyrc-browser-view 2>/dev/null || \
  tmux new-session -d -s phyrc-browser-view -c "$PWD" \
    .venv/bin/python tools/publish_review_gallery.py --destination "$phyrc_view_root"
```

4. 시연 4에는 아래의 새 ID 하나를 사용한다. 같은 ID의 원본이나 로그가 있으면 실행기는 중복 실행을 거절한다. 현재 상태는 해당 ID의 로그와 `attempt.json`에서 확인한다.

```bash
phyrc_run_id=20261124-astra62-bilateral-recovery-001
tmux new-session -d -s phyrc-autonomous -c "$PWD" \
  participant/ops/collect_autonomous.sh "$phyrc_run_id"
tmux ls
```

5. 첫 구간 `hold-0001`이 게시되면 `output/collections/$phyrc_run_id/run_metadata.json`의 `collection_start`에서 `verified_after_reset=true`, `start_step=0`, `table_index=2`, 마찰 0.35를 확인한다. 감독은 첫 실제 행동, 두 로봇·다섯 뷰와 구간 추가를 확인하고 **새 서버의 실제 Brev 주소에 `/view/PhyRC-review.html`을 붙인 링크**를 사용자에게 전달한다. 사용자는 그 링크를 새 브라우저 탭에서 연다. 11월 23일 서버의 호스트명은 이전 시연 링크다.

## 종료와 비교

[실행기](../../participant/ops/collect_autonomous.sh)는 모델 수집 후 캡처를 닫고 HDF5 전수 검증과 구간 ZIP 내보내기를 실행한다. `output/preflight/RUN.log`, `RUN-qc.log`, `output/collections/RUN/validation.json`, `output/review-exports/RUN.zip`을 확인한다. 원본과 ZIP을 비공개 저장소에 보존하고 새 서버에서 받을 수 있는 revision·해시를 기록한 뒤 서버를 정리한다. [수집과 보존](collection.md#마감과-데이터-확인)

같은 실행에서 **양손이 밑단 안으로 들어간 최초 관측, 어깨 방향 이동 후 양쪽 유지, 놓친 쪽 복구·첫 재이탈, 목둘레 통과, 서로 다른 소매에서 양손 노출**을 구간별로 남긴다. 감독은 원점수, 항목별 첫 인정 전이, 종료 순간의 유지 상태, `success`, 기술 QC와 훈련 승인 상태를 각각 기록한다. 같은 시드의 연습 회차에서 얻은 결과로 배치 일반화를 판단하기는 어렵다.

양손목이 몸통 밑단 안에서 유지된 장면은 이번 실험의 첫 관찰 성과다. 공식 `first_sleeve`는 같은 손의 손목과 손끝이 소매 출구를 통과해야 5점이다. 감독은 첫 소매를 기준으로 반대 어깨의 5점을 확인하고, 가슴이 옷 안에 있고 머리·목이 목둘레로 나왔을 때의 `neck` 10점을 따로 확인한다. 시연 3의 5/50과 비교할 때는 첫 미확인 단계가 어디로 옮겨갔는지, 시연 2의 20/50과 비교할 때는 목과 두 번째 소매가 새로 인정됐는지를 적는다. [공식 배점과 최종 성공의 0.5초 유지 조건](../competition/EVALUATION.md)
