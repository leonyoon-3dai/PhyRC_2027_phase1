시연 25는 시연 20의 명령을 1,300까지 재생한 뒤 새 행동 1,046전이를 기록했습니다. 시연 26은 시연 25의 명령을 2,346까지 재생한 뒤 새 행동 559전이를 기록했습니다. 새 두 회차는 슬롯에서 시작하므로, 원본 영상과 복원 후 0전이의 파지, 밑단, 줄무늬 팔과 집게 위치를 대조합니다. 점수는 새 회차에서 다시 기록합니다. [시연 25–27 분석](20261126-demo25-27-analysis.ko.md#체크포인트와-분기점-비교)

### 공통 착의 지시

1. **팔꿈치까지.** 각 로봇은 자기 쪽 노란 몸통 밑단의 바깥 끝에 가까운 곳을 잡습니다. 줄무늬 전완과 팔 굽힘을 따라 양팔 진행 깊이를 맞춥니다. 한쪽이 앞서면 현재 지지를 유지하고 다른 쪽을 맞춥니다.
2. **목 통과.** 머리에 가까워지면 반대편 파지를 유지하면서 두 로봇이 차례로 밑단 중앙의 양옆을 다시 잡습니다. 천이 두 집게를 따라오는지 보고, 실제 목둘레가 정수리를 지나 목에 오는지 여러 카메라에서 확인합니다.
3. **어깨 안착.** 목둘레를 유지하면서 필요한 경우 각 로봇이 자기 쪽 밑단 끝으로 돌아가 양쪽 어깨를 차례로 덮습니다. 손이 자기 소매 밖으로 나오는지 각각 확인합니다.

파지, 이동 방향과 여유 공간이 명확하면 **행동당 12–20전이**를 사용합니다. 새 파지, 접촉, 가림이나 장력이 불확실하면 짧게 시험하고 관측한 뒤 긴 동작을 이어갑니다. 원본 프롬프트는 해시를 확인해 보존하고 [이번 공통 지시](../../participant/collection/prompts/demo33_34_dressing_addendum.txt)를 이어 붙입니다. 공통 지시는 현재 착의 순서와 동작 길이에 우선 적용됩니다.

## 새 서버에서 두 시연 시작

[새 서버 준비](start.md#1-환경-준비)로 공식 시뮬레이터, RTX GPU, Codex CLI와 모델 권한을 확인합니다. 계정으로 비공개 Hugging Face 백업에 읽기 권한을 확보한 뒤 저장소 루트에서 실행합니다. 아래 복원은 고정 리비전의 슬롯·영수증·원본에서 필요한 파일만 검증해 작업 경로에 놓습니다. 원본 프롬프트가 담긴 두 캡처 아카이브를 처음 받으면 합계 약 **13 GB**가 필요합니다. 미리 내려받은 경로가 있으면 `--download-root`로 재사용합니다. [시연 25 백업](20261126-demo24-25-private-backup.json) · [시연 26 백업](20261126-demo26-32-private-backup.json)

```bash
hf auth whoami
python3 scripts/restore_demo33_34_sources.py
phyrc_pair_id="$(date -u +%Y%m%dT%H%M%SZ)-demo33-34"
python3 participant/ops/demo_pair.py preflight --pair-id "$phyrc_pair_id" --gpu 0
python3 participant/ops/demo_pair.py run --pair-id "$phyrc_pair_id" --gpu 0
```

두 회차는 같은 GPU에서 별도 시뮬레이터와 모델 세션을 사용합니다. 원본은 GPT‑6.2 Sol Ultra, 공개 카메라 5개, 손목 깊이 패널, 행동 상한 20전이, 검토 구간 최대 5결정·80전이, 매 행동 후 추가 정착 0전이를 사용했습니다. 복원 시 초기 정착 상태는 따로 확인합니다. 시연 33의 새 100전이와 마감, 시연 34의 마감에서 슬롯을 저장합니다. 시연 34의 실행 상한은 원본 `run_metadata.json`에서 읽습니다. 새 실행을 시작할 때는 새 ID를 사용합니다.

## Chrome 비교 화면

인증된 Brev 웹 주소에서 `PhyRC-compare.html`을 엽니다. Jupyter Server Proxy 경로는 기본 `<Jupyter 기본 주소>/proxy/8773/PhyRC-compare.html`입니다. 실행기가 게시 서버를 루프백에만 엽니다. 기존 `/phyrc/` 게시 경로를 사용하면 `<서버 웹 주소>/phyrc/PhyRC-compare.html`입니다. 서버의 Codex는 인증된 HTTPS 경로에서 페이지와 상태 JSON, 첫 GIF 두 개가 열리는지 확인한 뒤 실제 주소를 전달합니다. Chrome 사용자는 SSH 연결 없이 **왼쪽 시연 33, 오른쪽 시연 34**를 스크롤 없이 볼 수 있습니다. [Jupyter 프록시 경로](https://jupyter-server-proxy.readthedocs.io/en/latest/arbitrary-ports-hosts.html)

두 GIF는 각각 복원·정착 뒤 0전이부터 최근 게시 전이까지를 **시뮬레이션 시간 기준 4배속**으로 보여 줍니다. 각 영상은 전체 뷰와 두 로봇의 머리·손목 카메라를 포함합니다. 8전이마다 한 화면을 표시하고 마지막 전이는 항상 포함합니다. 수집 중에는 최신 완성 구간까지 갱신하고, 종료 뒤 마지막 전이까지 반영합니다. 화면에 표시하는 GIF의 끝 전이와 현재 수집 전이를 비교하면 게시 지연을 알 수 있습니다.

## 동시 실행 성능 확인

| 측정 | 비교 방법 |
| --- | --- |
| 수집 속도 | 회차별 분당 전이 수를 기록합니다. 둘 다 활성인 구간과 한 회차만 남은 구간을 비교합니다. |
| 병목 | GPT 호출과 시뮬레이터 명령의 실제 겹침을 따로 집계하고, 모델 응답 시간과 환경 처리 초/전이를 나눠 봅니다. |
| 서버와 GIF | GPU 사용률·VRAM, CPU, GIF 게시 시간·끝 전이 지연을 함께 확인합니다. GIF가 밀리면 수집을 유지하며 게시 빈도를 먼저 조정합니다. |
| 마감 | 회차별 파일, HDF5 구간, 유효한 로컬 점수와 `success`, 공개 영상의 실제 마지막 전이를 확인합니다. |

선행 L40S 측정에서 시연 28은 **동시 7.10, 단독 7.37전이/분**이었습니다. 당시 두 GPT 실행의 모델 호출은 겹쳤지만, 같은 관측 구간의 시뮬레이터 동작은 겹치지 않았습니다. 새 비교에서는 시작 직후 첫 유효 구간과 두 회차 종료 후 결과를 남깁니다. 한 회차만 실행된 비교 표본이 부족하면 병행으로 인한 변화는 측정 대기로 기록합니다. [시연 27·28 측정 원문](20261126-demo28-concurrency.ko.md)

실시간 수치는 `output/demo33-34/<쌍 ID>/telemetry.json`, 마감 비교는 같은 폴더의 `performance.json`에서 확인합니다. 시작 확인과 오류에는 `pair-state.json`, `demo33.log`, `demo34.log`, `publisher.log`를 사용합니다.
