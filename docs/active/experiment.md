# Astra 착의 실험 계획

현재 시험할 가설은 **처음에 두 팔을 모두 밑단 안에 걸쳐 두면, 목둘레를 넘긴 뒤 반대 손을 다시 찾기 쉬워지는가**이다. 같은 연습 배치에서 사용자 피드백 시연은 5/50, 한 팔과 얼굴을 먼저 시도한 GPT 시연은 20/50이었다. 세 번째 실행도 0전이에서 독립적으로 시작한다. 구간마다 양팔의 걸침 유지, 목둘레의 실제 이동, 각 소매의 출구를 확인한다. [세 회차 비교](20261123-demonstrations.ko.md) · [현재 조작 순서](autonomous.md)

## 어디에서 시작할까

| 실행 | 출발·질문 | 채택할 증거 |
|---|---|---|
| 첫 행동 전 | 매 회차 새 run ID로 환경을 초기화한다. 옷이 지정한 최근접 테이블 위에 있는지 첫 공개 5뷰로 확인한다. 감독은 새 물리 프로필, 공식 코드 revision, 모델과 초기화 조건을 기록한다. | 첫 구간의 시작 전이 0, 부모 없음, 해당 회차의 첫 관측. 배치 조건을 확인하기 어려우면 HOLD하고 첫 행동을 보내기 전에 감독이 점검한다. |
| 10점 검증 | 새 옷에 양옆에서 접근해 파지·픽업·손목 정렬·첫 소매까지 순서대로 수집한다. 손 위에 자유 가장자리가 생기는지 보고 두 로봇을 함께 옮기거나 지지점·높이를 조정한다. | 같은 run의 유효 평가에서 `pickup=5`, `first_sleeve=5`. 운영용 초기 배치·시드와 평가 자료는 감독 영역에 둔다. |
| 50점 검증 | 같은 회차에서 양팔 걸침 후 목둘레를 넘기고 각 소매를 다시 맞춰 위팔과 앞면까지 정리한다. 재시도는 매번 동일한 최근접 테이블 조건과 0전이에서 새로 시작한다. | 회차별 `raw_points`, 항목별 점수와 `success`를 남긴다. 모든 시도의 원점수 분포와 10점·50점 도달 횟수를 함께 기록한다. 공식 순위는 주최 측 평가 배치의 평균 원점수 우선, 동점이면 points/s 순이다. 이 수집의 측정값은 최근접 테이블에서의 연습 결과다. [공식 평가](../competition/EVALUATION.md) |

**최근접 테이블의 기준.** 공식 초기 배치에서 두 로봇 베이스 각각과 테이블 중심 사이의 수평 거리를 구하고 두 거리의 평균을 비교한다. 중앙 테이블 두 곳(인덱스 1·2)은 약 1.923 m로 공동 최단이며, 바깥 두 곳은 약 3.492 m다. 수집 회차에서는 중앙 두 곳 중 +X 방향의 세 번째 테이블(0부터 세어 인덱스 2)을 일관되게 사용한다. 감독은 이 테이블을 고르는 공식 샘플러의 시드를 사용하고(기본 43) 새 초기화 직후 실제 테이블 인덱스를 확인한다. Astra는 공개 카메라와 로봇 상태로 사람과 옷을 찾고, 시드와 내부 정답 좌표는 감독 영역에 둔다.

**물리 조건.** 주최 측 체크포인트 2(2026-12-01)의 기본값은 셔츠–마네킹과 천끼리 마찰 0.35, 그리퍼·테이블 마찰 0.5다. 새 기록에는 `upstream_revision`과 `physics_profile`을 남긴다. 예전 마찰 0에서 수집한 시연은 관찰 근거로 보관한다. [공식 변경과 동기화 범위](upstream.md)

## 구간별 조작과 채점

아래 누적값은 항목별 배점의 예시다. 3회차의 실제 조작 순서는 양팔 걸침 → 목둘레 → 양쪽 소매 재정렬 → 몸통 안착이다. 공식 평가는 첫 소매가 확인되면 반대 어깨와 두 번째 소매를 각각 검사하고, 위팔·목·앞면 항목도 각 조건에 따라 기록한다. 한 번 얻은 항목 점수는 유지된다. 관측에는 카메라의 좌우 대신 마네킹의 해부학적 좌우를 적는다. 로봇별 분할 영상은 왼쪽 robot_1, 오른쪽 robot_0이다.

| 구간 `stage` | 목표 점수 | Astra가 시험할 조작과 구간 경계 | 감독이 확인할 조건 |
|---|---:|---|---|
| `setup` | 0 | 두 로봇을 옷 양옆으로 보낸다. 밑단 양쪽을 잡되 손 위에 늘어질 자유 가장자리를 확보한다. 가운데 쪽 재파지가 필요하면 반대쪽 지지가 보일 때 한쪽만 옮긴다. | 시작 관측, 실제 파지 후 천의 동행, 초기 배치 기록 |
| `pickup` | +5 → 5 | 양쪽 파지를 유지해 천을 들어 올려 운반한다. 들어 올린 뒤 정착 구간을 기록한다. | 같은 그리퍼가 잡은 천 부위를 파지 높이보다 5 cm 이상 들어 시뮬레이션 시간 3초 유지 |
| `first_sleeve` | +5 → 10 | **밑단 진입 → 같은 손의 소매 입구 정렬 → 소매 밖 노출**을 각각 관찰한다. 손 위의 자유 경계와 그리퍼 본체 여유를 확인한 뒤 짧게 내려 걸친다. 필요하면 높이·입구 방향·양쪽 펼침 중 하나를 바꾼다. | 첫 손의 **손목과 손끝**이 같은 소매 출구를 통과. 밑단에 걸치거나 한 뷰에서 손이 보여도 득점은 미확정 |
| `opposite_shoulder` | +5 → 15 | 첫 팔의 소매 관계를 유지하며 반대 지지점을 이동해 천을 반대 어깨 너머로 넘긴다. | 처음 통과한 팔 반대쪽의 어깨 관절 너머로 옷 일부가 지나감 |
| `second_sleeve` | +5 → 20 | 첫 팔을 다시 확인하며 남은 소매 입구를 다른 손에 정렬한다. 한쪽에서 두 손이 함께 보이면 입구의 연결 관계부터 재확인한다. | 다른 손목·손끝이 **서로 다른** 두 번째 소매의 출구를 통과 |
| `left_upper_arm` | +5 → 25 | 왼팔 쪽 소매의 가장자리와 위팔이 함께 보이는 구간에서 옷을 어깨 쪽으로 이동한다. | 왼쪽 소매가 왼쪽 위팔 일부를 덮으면 5점 |
| `right_upper_arm` | +5 → 30 | 반대 소매도 올린 뒤 두 팔의 소매 유지와 천의 비틀림을 확인한다. | 오른쪽 소매가 오른쪽 위팔 일부를 덮으면 5점 |
| `neck` | +10 → 40 | 목둘레와 얼굴의 관계를 확인하면서 옷을 어깨 너머로 정리한다. 머리 위에 겹쳐 보이면 가림으로 기록한다. | 가슴이 옷 안에 있고 머리·목이 목둘레로 올바르게 빠져나오면 즉시 득점 |
| `front_orientation` | +10 → 50 | 머리가 나온 상태에서 V넥 앞뒤를 확인하고 필요하면 한쪽 지지를 유지하며 방향을 조정한다. | 머리가 나오고 V넥 앞면이 정면 기준 45° 이내, 투영 길이 2 cm 이상으로 0.5초 유지 |
| `success_hold` | +0 | 양팔과 목의 통과, 앞면 방향이 **동시에** 유지되는 마지막 구간을 기록한다. | 서로 다른 두 소매 밖의 두 손, 머리·목 노출, 올바른 앞면이 0.5초 함께 유지되어 `result.success=true` |

**점수 근거.** `score_before`와 `score_after`는 같은 실행 경계의 유효한 감독 평가에서만 채운다. 경계의 증거가 없으면 `null`로 남긴다. `score_source`에는 해당 평가 파일·표본 위치를 적는다. 최종 결과만 있으면 회차 합계만 확인할 수 있다. 영상만으로 최초 득점 시각을 추정하지 않는다. ## 구간을 언제 닫고 무엇을 물을까

하나의 구간에는 관찰로 판별할 수 있는 의도 하나를 둔다. 운반처럼 같은 의도가 지속되면 여러 짧은 행동을 한 클립으로 묶는다. 손목 근처에서는 2–4전이(20 Hz에서 0.10–0.20초)의 교정으로 시작하고 행동 직후와 정착 후를 비교한다. 아래 판단 지점에서 HOLD하고, 웹에는 마지막 실행 프롬프트·클립·분석·다음 제안 하나를 올린다. 기다리는 동안 물리 시간은 진행하지 않는다.

| 판단 지점 | 확인할 내용 | 다음 프롬프트에 남길 것 |
|---|---|---|
| 의도한 변화가 유지됨 | 실제 양쪽 파지점 변위와 함께 자유 경계가 목표 손 쪽으로 이동했는가? 정착 뒤에도 남아 있는가? | 다음 한 가지 조작과 예상되는 영상 변화 |
| 이동 후 정체·되튐 | 명령한 쪽과 반대쪽이 각각 얼마나 움직였는가? 천 입구도 움직였는가? | 같은 지시 반복 전에 높이·접근면·지지점 중 한 요소만 바꾸는 실험 |
| 가림·파지 손실·단계 변경 | 같은 손목과 출구를 추적할 수 있는가? 분명히 보이는 지지점이 남았는가? | 공개 카메라에서 재확인할 관계, 유지할 지지, 현 상태에서의 교정 또는 HOLD |
| 사용자 검토 | 제안을 채택하거나 자유 입력으로 교정한다. 더 검토하려면 대기하고, 회차를 끝내려면 종료를 선택한다. | 사용자가 확정한 **공개 관측 기반** 지시. 평가 점수·숨은 위치·평가 로그는 행동을 결정하는 모델에 전달하지 않는다. [공식 입력 규칙](../competition/RULES.md) |

**라벨 작성 예시(가상).** “몸체가 옆으로 이동했다. R1 손목 영상에서 가장자리가 손끝 가까이 왔지만 정착 뒤 되돌아갔다. R0 헤드에서는 소매 출구가 가려졌다.” 여기서는 `stage=first_sleeve`, `outcome=partial`, `labels=["settle_rollback","occluded"]`로 기록할 수 있다. 다음 제안은 “반대쪽 지지를 유지하고 입구 방향만 바꿔, 같은 손끝과 자유 경계가 정착 뒤에도 함께 보이는지 확인”이다.

- `outcome`은 그 구간에서 명시한 **조작 의도**에 대한 판정이다. 목표 관계가 확인되고 정착 후 유지되면 `success`, 일부만 확인되면 `partial`, 반대 결과나 파지 상실이 관측되면 `failure`, 가림·누락으로 판단할 수 없으면 `uncertain`을 쓴다.
- `analysis`에는 근거가 된 뷰, 시작/조작 직후/정착 후의 변화, 보이지 않은 관계를 쓴다. `labels`에는 확인한 현상만 붙인다. 예를 들어 `edge_visible`, `grasp_slip`, `opening_collapsed`, `settle_rollback`, `occluded`를 쓴다. 두 뷰의 근거가 충돌하면 어느 뷰에서 무엇이 보였는지 기록하고 결론을 유보한다. 한계를 적어 근거 없는 확률 수치를 피한다.
- 모든 구간은 해당 회차에서 처음 실행한 조작을 담는다. `parent`는 같은 run에서 바로 앞서 검토한 구간을 가리킨다. 사용자 교정 전후를 나란히 찾을 수 있게 이 연결을 유지한다. 한 run의 클립과 인접 프레임은 학습·검증을 나눌 때 같은 쪽에 둔다. 파일 QC, 구간 판정, 유효한 평가 결과, 학습 승인 여부를 따로 확인한다.
